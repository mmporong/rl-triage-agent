# 판단 갱신 v1 실행 기록

등록한 8개 사례에서 AI의 판단 변화는 입증되지 않았다. 모델 경로 8개가 모두 HOLD로 끝났고, 감사 결과도 `valid=false`, `proof_changed=0`이다. 이미 본 seed 2027의 통합 실행이며 정확도 평가가 아니다.

| 경로 | 사례 수 | completed / HOLD | 모델 호출 | 실제 검사 | Isaac launcher 합계 | 환경 step |
|---|---:|---:|---:|---:|---:|---:|
| 모델 | 8 | 0 / 8 | 10 | 2 | 55.5초 | 102,400 |
| 고정 순서 | 8 | 3 / 5 | 0 | 6 | 436.3초 | 409,600 |
| 저렴한 판별 검사 우선 | 8 | 4 / 4 | 0 | 8 | 131.7초 | 0 |

`completed`는 실행 고리의 종료 상태다. 원인 확정이나 정답 일치를 뜻하지 않는다. 모델의 두 실제 검사는 정상 관측으로 끝났다. 서로 다른 완료·보류 상태와 GPU 대기 오류가 섞였으므로 위 시간의 차이를 절감 효과로 비교하지 않는다. CPU, 호출별 토큰·지연은 개별 기록에 있고 장치 연산 시간과 사람 검토 시간은 미측정이다.

확인된 중단 경로는 관측 없는 `confirm`, 유효하지 않은 JSON, 공개 카탈로그와 다른 예상 결과, 이미 관측한 검사 선택, GPU 사용 충돌이다. `h01_s2027`에서는 최신 결과를 가린 호출이 잘못된 확정을 시도했고, 그 거절이 실제 관측 후 호출까지 막았다. 이는 실제 진단과 검증용 대조 호출을 한 예외 경계로 묶은 실행기 문제다.

또한 Isaac 관련 PID가 감지되거나 다른 세션의 Ollama 모델이 로드된 때 다음 사례를 기다리지 않고 HOLD로 넘겼다. 작업 중인 다른 세션은 종료하지 않았다. 이 사례들의 0초·0검사는 성공적인 진단 비용이 아니다.

후속 실행은 대조 검증과 실제 진단의 오류를 분리하고 GPU가 비워질 때까지 대기하도록 보강한다. v1 파일을 수정하거나 의미 오류 응답을 다시 호출해 성공으로 바꾸지 않는다. 수정한 코드와 새 프로토콜을 커밋한 뒤 별도 태그에서 실행한다. 새 실행도 이 입력들의 정확도·일반화 근거로 사용하지 않는다.

재생의 실패 문구와 중단 사유 표시는 [보고 어댑터](../evals/render_failed_active.py)가 만든다. 동결된 모델·검사·감사 코드를 바꾸지 않으며 원장의 수치나 감사 판정도 변경하지 않는다.

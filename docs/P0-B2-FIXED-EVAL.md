# P0-B2 고정 평가 조건 계약 (2026-10-08)

P0-B1은 학습 텔레메트리라서 각 실행 자신의 환경(제한 시간·명령 주기·물리)에서 기록된 값을 봤다. 이 단계는 모든 실행의 최종 체크포인트를 같은 조건에서 평가해 회복 판정을 실측한다([IMPLEMENTATION-ORDER.md](IMPLEMENTATION-ORDER.md) 3절 P0-B2). 실행 위치는 Windows 로컬 RTX 3060이다(사용자 결정 2026-10-08).

- 프로토콜: `bench/protocols/fixed_eval_v1.json`
- 평가기: `evals/fixed_eval.py`(Isaac Sim 번들 파이썬), 실행기: `evals/run_fixed_eval.py`, 판정 집계: `evals/fixed_eval_summary.py`
- 판정 계약(이 문서와 위 코드)을 커밋한 뒤 기존 실행 전부를 평가한다. 결과는 새 tag 폴더에 둔다.
- GPU를 쓴다. 모델 호출·네트워크는 쓰지 않는다.

## 1. 평가 조건 (`fixed_eval_v1`)

| 항목 | 값 | 이유 |
|---|---|---|
| task | `Isaac-Velocity-Flat-Unitree-Go2-v0`, sim.dt 0.005 × decimation 4 | 벤치 학습과 같은 task·제어 주기 |
| 명령 | vx·vy ∈ {−1, 0, 1} m/s × yaw ∈ {−1, 0, 1} rad/s, (0,0,0) 제외 26조건, 매 스텝 덮어씀 | 학습 명령 범위(x·y·회전 ±1)를 덮는 고정 격자 |
| 환경 수 | 조건당 40, 1040개 | |
| 시간 | 1000스텝(20초), 환경마다 첫 에피소드만 | 기준 제한 시간 |
| 고정한 것 | 질량 무작위화 끔, 관측 노이즈 끔, heading 명령 끔, 정지 명령 비율 0, eval seed 2026 | 실행 간 같은 조건 |
| 실행을 따르는 것 | `env.actions.joint_pos.scale` | 정책 인터페이스(행동→관절 목표 대응) |

지표: 낙상 비율(시간 제한 전 base_contact), 평균 생존 시간, 선속도 RMSE, 회전 RMSE(살아 있는 스텝 기준). 제자리에 서 있는 정책의 RMSE(명령 크기의 RMS)는 선속도 1.177 m/s, 회전 0.832 rad/s이고 결과 파일에 함께 남긴다.

sim.dt·decimation을 바꾼 실행(c10, v2 S14)도 기본 제어 주기에서 평가한다. 이 실행들이 학습한 제어 주기와 다르므로, 그 실행의 판정은 "기본 task에서 쓸 수 있는 정책인가"를 뜻한다.

**결정성 확인(계약 전):** `baseline_s42`의 같은 체크포인트를 한 프로세스에서 두 번 평가하면 네 지표가 모두 같았다.

## 2. 판정

P0-B1과 같은 함수(`rl_triage.recovery.compare`·`derive_bands`·`verdict`)와 여유값(비 지표 +0.10, 낙상 비율 +0.05)을 쓴다. 지표는 생존 시간=평균 생존 시간, 낙상=낙상 비율, 오차=선속도·회전 RMSE로 바꾼다. 모든 실행이 20초 조건이라 undetermined는 없다.

정상 실행 비교값: 서로 다른 seed의 기준 실행끼리(양방향), `benign_all_s<N>` 대 같은 seed 기준, 같은 seed 반복 학습 `baseline_repeat<N>_s<seed>` 대 기준. 반복 학습은 seed 42로 한 번 한다(100회, 1024 env, 기존 기준과 같은 명령).

비교: 실행마다 P0-B1 라벨과 현행 `recovered`를 나란히 적고, P0-B1 라벨과 다른 실행을 목록으로 남긴다.

## 3. 계약 전에 본 값

- `baseline_s42`(100회)의 고정 평가: 낙상 0, 선속도 RMSE 1.175, 회전 RMSE 0.823. 제자리 값(1.177, 0.832)과 거의 같다. 100회 학습 기준 정책은 넘어지지 않지만 속도 명령을 따르지 않는다.
- 학습 예산 파일럿(4절)의 기준 실행 결과와, 같은 seed 반복 학습의 체크포인트가 원래와 바이트 단위로 같다는 것. 결함 실행은 계약 전에 고정 평가하지 않았다.

## 4. 학습 예산 파일럿

P0-C 새 holdout의 학습 예산을 정하기 위한 측정이다. 판정 계약과 별개이며 결과는 `evals/results/p0b2_pilot_20261008/`에 둔다.

| 실행 | 체크포인트 | 낙상 | 생존(초) | 선속도 RMSE | 회전 RMSE |
|---|---|---|---|---|---|
| 1024 env, seed 42 | 50 | 0 | 20.0 | 1.176 | 0.827 |
| | 100 | 0 | 20.0 | 1.175 | 0.822 |
| | 150 | 0 | 20.0 | 1.119 | 0.771 |
| | 200 | 0.084 | 18.4 | 1.075 | 0.734 |
| | 250 | 0.154 | 17.1 | 1.021 | 0.745 |
| | 299 | 0.093 | 18.2 | 0.961 | 0.602 |

| 4096 env(Isaac Lab 기본값), seed 42 | 50 | 0 | 20.0 | 1.174 | 0.822 |
| | 100 | 0.106 | 18.3 | 0.882 | 0.657 |
| | 150 | 0 | 20.0 | 0.249 | 0.343 |
| | 200 | 0 | 20.0 | 0.174 | 0.303 |
| | 250 | 0.038 | 19.3 | 0.164 | 0.315 |
| | 299 | 0 | 20.0 | 0.154 | 0.292 |

- 1024 env로는 300회에서도 제자리 대비 선속도 오차가 18%만 줄고 낙상이 생긴다. 지금 벤치(1024 env × 100회)의 정상 기준은 서 있는 정책이다.
- 4096 env로는 150회부터 제자리 대비 선속도 오차가 79% 줄고 낙상이 없다. 300회 학습은 RTX 3060에서 502초, 1024 env 300회는 358초였다(래퍼 측정, Isaac Sim 시작 포함).
- 같은 seed·설정으로 100회 학습을 다시 하면(`baseline_repeat1_s42`) 최종 체크포인트가 원래 기준 실행과 바이트 단위로 같았다(SHA256 동일). 이 호스트에서 같은 seed 반복의 변동은 0이고, 정상 변동은 seed 사이에서 생긴다.

파일럿은 계약 커밋 전 평가기로 쟀다. 커밋 전 검수에서 바뀐 것은 명령 텐서를 실행마다 다시 가져오는 위치와 0 나눗셈 방어뿐이다. 본 평가에 포함되는 `baseline_s42`의 값을 결정성 확인 값과 대조한다.

[권고] P0-C 새 holdout은 4096 env × 300회(Isaac Lab Go2 flat 기본값)로 학습한다. 정상 기준이 실제로 걷는 조건이어야 보상 정의 결함(c03 같은)이 행동으로 드러나는지 판정할 수 있다.

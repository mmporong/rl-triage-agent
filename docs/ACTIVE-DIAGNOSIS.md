# 관측으로 판단을 갱신하는 실행

목표는 텔레메트리만 본 가설과 실제 Isaac 검사 이후의 가설을 나란히 남기는 것이다. Nemotron이 공개 검사 목록에서 다음 검사 하나를 고른다. 호스트가 사전 승인된 시험 범위 안에서 원장을 기록하고 고정된 검사를 실행한다. 모델은 측정값을 받은 뒤 여섯 메커니즘의 순위를 새로 낸다. 모델의 순위와 동결 규칙이 유지·기각한 가설은 별도 기록이다.

## 범위와 판정

등록 입력은 기존 seed 2027의 결함 6사례, 정상 1사례, 외부 결함 1사례다. 모두 이미 본 입력이다. 이 실행은 시스템 통합과 사례별 판단 변화를 확인하며, 정확도·일반화·새 고객 환경의 성공률을 평가하지 않는다. 원인 되돌리기 재학습이나 정책 회복까지 검증하는 실행도 아니다. v1·v2의 프로토콜과 결과는 보존하고, 바뀐 소스와 실행 백엔드는 새 프로토콜과 새 태그에 등록한다.

강한 장면은 다음 조건을 함께 만족해야 한다.

1. 저장된 응답을 재사용하지 않고 새 API 호출에서 모델이 검사를 선택했다.
2. 승인된 결정·입력·체크포인트·검사 인자와 실제 실행 기록의 해시가 일치한다.
3. 검사 결과를 인용한 모델 원문의 우선 가설이 바뀌었다.
4. 새 관측은 이전 우선 가설의 예측과 반대이며, 새 우선 가설은 동결 규칙과 모순되지 않는다.
5. 같은 단계에서 최신 검사 결과만 가린 새 호출은 이전 우선 가설을 유지했다.

관측 후 순위가 유지돼도 실패한 검사를 다시 돌리거나 답을 수정해 재시도하지 않는다. 결과가 불명, 실행 실패, 시간 예산 초과이면 원인을 확정하지 않고 보류한다. JSON 계약이나 근거 인용 오류도 보류한다. 재시도는 통신·시간 초과·429·5xx·빈 응답·잘림에만 최대 두 번의 총 시도를 허용한다.

사례 순서는 고정하며, 발표용 기본 장면은 위 조건을 통과한 첫 사례다. 통과하지 않은 사례도 전체 표에 남긴다. 결과별 문구는 프로토콜에 평가 전에 고정한다. 한 번의 관측/가림 호출 쌍은 사례 증거다. 원격 모델 호출의 완전한 결정성이나 일반적인 인과 효과를 뜻하지 않는다.

판단 변경과 문제 해결 가능성은 별도 판정이다. 새 실행 전에 다음 보조 기준을 고정한다. 이 기준은 모델 입력이나 동결 판정기를 바꾸지 않는다.

- 변경된 우선 가설이 등록된 주입 범주와 일치하는지는 모델 호출을 모두 마친 뒤 로컬 비공개 정답으로 채점한다. 이는 이미 본 합성 사례의 범주 일치이며, 실제 원인 제거·정책 회복·새 실패 정확도의 증거가 아니다.
- 규칙 상태가 확정이면 모델이 확정하고, 검사를 더 해도 구분할 수 없거나 후보가 없으면 보류해야 유용한 후속 결정으로 센다. 열린 상태에서는 남은 예산 안에서 아직 실행하지 않은 구분 검사 또는 유일 후보의 확인 검사를 제안해야 한다. 불명 관측은 보류해야 한다.
- 정상 사례와 지원 범위 밖 사례의 잘못된 확정, 실행 실패 뒤 강행, 누락 비용을 별도 표에 남긴다. 두 경계 사례만으로 일반적인 안전성을 주장하지 않는다.
- 같은 백엔드·입력·검사 예산의 단순 규칙이 같은 등록 범주에 같거나 적은 검사로 도달하면 해당 사례를 AI 필요성의 근거로 쓰지 않는다. launcher 시간과 전달 시간을 분리해 표시한다.

보조 기준을 통과한 장면을 별도로 재생한다면 등록 순서상 첫 통과 사례를 사용한다. 기본 판단 변경 장면의 선택 규칙은 유지한다. 모든 사례의 보조 판정과 미확인 항목을 함께 남기며, 별도 개입·회복 실험을 실행하지 않은 경우 회복 여부는 미측정으로 표기한다.

## 진단과 대조 검증

실제 관측을 받은 호출과 최신 관측만 가린 호출은 독립적으로 기록한다. 실제 호출의 유효한 결정만 다음 승인과 검사 선택에 쓰인다. 가림 호출이 JSON·근거·행동 계약을 어겨도 실제 호출을 생략하거나 진단을 보류하지 않는다. 그 쌍은 판단 변화의 증거에서 제외한다. 실제 호출이 계약을 어기면 진단을 보류한다.

각 호출은 유효 결정 또는 거절 기록, 입력 해시, 모든 시도 파일과 해시를 남긴다. 의미 오류는 재시도하지 않는다. 인프라 오류 한도를 소진한 호출도 기록한다. 입력·메시지 해시 불일치, 쓰기 충돌, worker 정리 실패는 실행 하네스 오류이며 다음 호출을 시작하지 않는다. 오류가 기록됐다는 사실만으로 증거가 유효해지지는 않는다. 감사기는 원문에서 같은 거절이 재현되는지와 비용·원장 결속을 검증한다.

재생 화면은 진단 상태와 발표 증거 상태를 구분한다. 기록이 온전한 HOLD는 감사할 수 있지만 판단 변화의 성공 장면은 아니다. 대조 검증 실패를 제품 진단 실패로 합산하거나, 진단 완료를 대조 검증 통과로 바꾸지 않는다.

## 비교와 비용

모델 선택, 고정 체크리스트, 가장 저렴한 판별 검사의 세 방식이 같은 텔레메트리 요약·공개 검사 목록·전체 여섯 후보·최대 두 검사·검사당 180초의 launcher 시간 예산을 갖는다. 두 규칙 방식은 모델 순위를 사용하지 않는다. 각 방식은 새 원장과 새 태그에서 별도 실제 검사를 실행한다. CPU나 GPU 사용량을 줄였다는 결론은 결과 확인 전에 정하지 않는다.

180초는 Isaac 시작·실행·종료를 포함한 원장 수락 기준이며, 프로세스를 180초에 강제 종료하는 타이머가 아니다. 초과 실행의 결과는 unknown으로 처리한다. 동결 카탈로그의 `cost_gpu_s`는 기존 선택 휴리스틱의 추정치다. 이번 실측의 launcher wall과 섞어 합산하지 않는다.

각 모델 호출은 공급자가 반환한 입력/출력 토큰, 모델 worker CPU, 응답 시간, 응답 ID, 종료 이유, 원문, 입력·메시지 해시를 보존한다. Isaac 실행은 launcher wall, wrapper/driver CPU, 실제 `env.step` 수를 계측한다. 장치가 연산한 시간과 사람 검토 시간은 측정하지 않았으므로 null이다. 승인자는 사용자에게 시험 실행을 위임받은 Codex 운영자로 표기하며, 승인 문자열은 사람 신원이나 사용성 시험의 증명이 아니다.

모델 호출·토큰 합계는 관측을 가린 검증 호출까지 포함한 실험 총비용이다. 제품의 한 번 진단 비용으로 옮겨 쓰려면 각 호출 기록에서 실행 고리와 가림 검증을 나눠 계산해야 한다.

## 공개 규칙과 원격 검사

모델에 주는 판정 설명은 공개 카탈로그에서 여섯 후보를 모두 유지한 채 시작한다. 정상·이상 관측과 다른 예측을 가진 후보만 제외하며, 예측이 null이면 유지한다. 불명 관측으로 후보를 제외하지 않는다. 하나만 남아도 그 후보만 이상을 예측하는 확인 검사의 실제 이상 관측이 있어야 확정할 수 있다. 이 설명은 실제 관측 호출과 가림 호출에 동일하게 제공된다. 계산된 후보 목록, 숨은 정답, 판단을 바꾸라는 지시는 모델 입력에 추가하지 않는다.

기본 검사 백엔드는 native Windows다. 선택적으로 기존 Brev 인스턴스의 격리 작업 경로에서 같은 동결 검사를 실행할 수 있다. 백엔드·인스턴스 이름·작업 디렉터리 이름은 평가 전에 프로토콜에 고정한다. 필요한 코드와 체크포인트의 해시를 확인하고, 신뢰된 호스트가 검사 job을 만든다. 모델이 셸 명령이나 검사 인자를 만드는 경로는 없다. 기존 결과와 다른 체크포인트를 덮어쓰지 않는다.

클라우드로 보내는 것은 검사에 필요한 코드·체크포인트·job이다. 모델 호출은 기존 WSL NVIDIA API 환경에서 실행하며 API 키를 Brev로 보내지 않는다. 내부 전략·사용자의 실제 실패 원본·답안 파일도 전송 대상에 넣지 않는다. 공개 기록은 GPU 상태, 허용된 검사 인자, 측정값, 비용과 결속 해시를 남긴다.

Isaac Sim의 첫 실행과 확장 캐시 준비는 평가 전에 빈 stage를 한 스텝 실행하는 `bench/cloud_runtime_smoke.py`로 확인한다. 이 실행은 로봇이나 체크포인트를 로드하지 않는다. 설치·환경 smoke 비용은 별도 준비 비용이며 진단 검사의 성공, GPU 절감, 정책 회복으로 계산하지 않는다. 준비 완료 여부와 실제 probe 성공 여부도 구분한다.

native Windows와 Brev는 OS·GPU·원격 전송 조건이 다르다. 서로 다른 백엔드의 실행 시간을 AI 또는 규칙의 비용 우위로 비교하지 않는다. 각 백엔드 안에서 세 방식의 같은 등록 조건을 비교한다. 클라우드 launcher 시간은 Isaac 프로세스의 시작·실행·종료 시간이다. 준비 전송과 결과 회수는 별도 기록하고, 대기·모델 호출·전송을 포함한 전체 지연도 함께 보고한다. 장치 연산 시간은 여전히 미측정이다.

## 실행

Windows 저장소 루트에서 기존 Python 환경과 WSL NVIDIA API 환경을 사용한다. 모델은 WSL의 기존 `~/.config/nvidia/env`를 사용한다. 키를 Windows나 결과 파일로 복사하지 않는다.

```powershell
cd "$HOME/rl-triage-agent"
.venv/Scripts/python.exe evals/run_active_diagnosis.py prepare --out bench/protocols/active_새버전.json
# 위 프로토콜과 그 소스 파일을 검증·커밋한 뒤 실행한다.
.venv/Scripts/python.exe evals/run_active_diagnosis.py run-all --protocol bench/protocols/active_새버전.json --tag active_새이름
```

기존 Brev 설치를 선택할 때는 준비 명령에 `--backend brev --brev-instance <기존_인스턴스> --brev-workspace-basename <격리_작업_디렉터리> --brev-owner-marker-sha256 <소유_기록_파일의_SHA256>`를 추가한다. 소유 기록은 준비한 디렉터리를 확인하는 provenance이며 사용자 실행 승인을 대신하지 않는다. 새 인스턴스를 만드는 명령은 포함하지 않는다. 실행에 필요한 SDK·소스·체크포인트를 준비하고 환경 smoke를 확인한 뒤 새 태그에서 평가한다.

실행 태그는 영문·숫자·밑줄·하이픈만 허용한다. 같은 결과 파일이나 사례 폴더는 다시 사용하지 않는다. 실제 사례 이름은 기존 runner가 지원하는 이름을 유지한다. native GPU에 다른 Isaac 프로세스 또는 로드된 Ollama 모델이 있으면 대기 기록을 남긴다. Brev에서는 다른 compute 프로세스나 큰 메모리 점유가 있는지 확인한다. 비워진 뒤 승인·소비·검사를 진행하며 다른 작업을 종료하지 않는다. 대기 시간은 Isaac launcher 예산 밖이며 전체 지연에는 포함된다.

공개 결과는 `evals/results/<tag>/cases/<case>/`의 모델 호출, 승인 결속, 원장, 결과와 같은 태그의 `probes/`, `execution/`, `resources/`다. 규칙 비교는 `<tag>_fixed`, `<tag>_cheap`에 남는다. 저장된 산출물의 재생은 API나 GPU를 다시 호출하지 않는다.

이 드라이버는 제한된 host evaluation 경로다. 모델이 생성한 셸·코드·검사 인자를 실행하지 않는다. 기존 NeMo Agent Toolkit/OpenShell 분석 워크플로의 샌드박스 실행을 이 기록에서 새로 검증했다고 주장하지 않는다. 새로운 고객 입력·실물 로봇·결함 지원 범위 밖의 작업에는 별도 입력 등록과 검증이 필요하다.

# 한 callback으로 보존하는 영상 수집

영상과 시뮬레이터 측정의 시각이 다르면 모델이 잘못된 장면을 근거로 검사를 고를 수 있다.
새 수집 경로는 한 Replicator `Writer.write(data)`의 RGB, semantic mask, 카메라,
렌더 시각을 묶어 보존한다. 원본 배열과 metadata의 해시를 실행 기록에 연결하고,
녹화를 모델 입력으로 내보내기 전에 다시 검증한다.

## 동기화 확인

정지 화면 검사에서는 네 번의 capture마다 서로 다른 표식을 켠다. 같은 callback의
semantic mask와 RGB가 같은 프레임 코드를 나타내야 한다. 이전 RGB를 새 mask와
합치거나, 이전 표식을 반복한 결과는 거부한다. 이 표식은 정책 녹화에는 들어가지 않는다.

검사는 A·A·B·A 카메라 순서를 사용한다. 각 capture의 물리 상태와 시뮬레이션 시각은
그대로여야 하고, 렌더 프레임과 rational 시각은 등록한 순서로 증가해야 한다.
카메라 경로·행렬·해상도, FXAA 설정, 자산 준비와 SDK 종료 증거도 함께 확인한다.

이전 검사는 A 화면으로 돌아왔을 때 RGB 전체가 같아야 했다. 해당 검사에서 관찰된
불일치와 실패 결과는 보존한다. 새 판은 배경 픽셀 전체의 반복성과 callback의 프레임
결합을 구분한다. 이 검사를 모든 장면의 영상 지연 보장으로 해석하지 않는다.

## 기존 정책을 사용하는 호환성 점검

이미 확보한 seed 2208 정상 정책 체크포인트로 정지 화면 4회와 625프레임 녹화를
순서대로 확인한다. 새 학습과 모델 호출은 없다. 정지 화면 검사가 실패하면 녹화를
시작하지 않고, 두 단계가 모두 통과해야 새 source 수집을 진행한다.

각 단계의 상한은 900초다. GPU 실행 전에 소유 자원·점유·예산·마감 시각을 확인하고,
기존 실행 비용과 새 실행 비용을 합산한다. 미완료 기록과 실패 결과를 자동 재실행하지
않으며, 완료 기록은 원본을 재검증해 재사용한다.

CPU 회귀와 설치된 USD의 표식 구성 확인은 실제 Replicator 실행의 호환성을 대신하지
않는다. GPU 점검을 통과하기 전에는 이 경로의 영상을 모델 사용 가능 상태로 표시하지 않는다.

# Nemotron 요청 경로 비교와 영상 관찰

새 Nemotron 요청 경로는 정책 영상의 프레임을 읽는 보조 관찰 기준을 충족했다. 출력 계약, 근거 인용, NAT 도구 인자 문제는 해결 기준을 충족하지 못했다. 기존 결정 모델의 기본값은 유지한다.

2026-10-16에 이미 본 입력으로 수행한 개발 측정이다. 설계자는 기존 실패 사례를 알고 있었고, 입력·판정 기준·실행기를 측정 전에 커밋했다. 수치는 [공개 요약](../evals/results/nemotron_endpoint_bottlenecks_20261016_v3/summary.json), [개별 판정](../evals/results/nemotron_endpoint_bottlenecks_20261016_v3/decisions.json), [요청별 사용량](../evals/results/nemotron_endpoint_bottlenecks_20261016_v3/requests.json)에서 확인할 수 있다.

## 예전 요청 경로와 새 요청 경로

| 병목 | 이번 기존 모델 측정 | 이번 새 모델 측정 | 사전등록 판정 |
|---|---|---|---|
| B1 출력 계약 | 무효 4/33, 유효 29/33 | 무효 5/33, 유효 28/33 | 미해결 |
| B2 근거 인용 | 인용 오류 6/24, 계약 무효 6/24 | 인용 오류 2/24, 계약 무효 5/24 | 미해결 |
| B3 NAT 도구 인자 | 검증 오류 이벤트 3건, 최종 유효 제출 1/2 | 검증 오류 이벤트 2건, 최종 유효 제출 1/2 | 미해결 |
| B4 영상 관찰 | 텍스트 입력 모델. 같은 프레임의 추론 비교는 수행하지 않음 | 유효 응답 18/18, 고정 평가 라벨과 대응 17/18 | 이 개발 입력의 보조 관찰 기준 충족(해결) |

이 표의 기존 모델 결과는 새 모델과 같은 판에서 다시 호출한 수치다. 과거 N2의 무효 6/55, D3의 무효 8/24와 합산하지 않는다.

B1에서 양쪽 모두 유효했던 26쌍의 결정은 일치했다. 기존 모델 오류는 JSON 파싱 2건과 빈 근거 claim 2건이었다. 새 모델 오류는 등록되지 않은 근거 인용 2건, probe 기대 결과 불일치 2건, probe 식별자 자료형 오류 1건이었다. 진단의 평균 pass³는 양쪽 모두 0.667, 교정은 기존 0.600·새 모델 0.800이었다. 무효 응답 수와 진단 반복 일관성 조건을 통과하지 못했다.

B2에서는 인용 오류 수가 줄었지만 0건 조건에 못 미쳤다. 계약 유효 여부와 별개로 파싱된 원인 1위 정답은 기존 21/24·새 모델 20/24였고, 계약까지 유효한 원인 1위 정답은 15/24·18/24였다. 원인 순위를 맞히는 것과 근거를 유효하게 제시하는 것은 별개다. 이 비교는 기존 줄 번호 계약을 유지했으며, 새 hunk 계약의 효과를 측정한 결과가 아니다.

B3의 두 경로는 교정과 진단이다. 양 모델 모두 진단 제출은 유효했고 교정 제출은 거절됐다. 오류 이벤트에는 제출 전 점검과 최종 제출의 거절이 포함되며, 서로 다른 실패 사례 수를 뜻하지 않는다. 네 workflow의 HTTP 계측을 완료했고 각 입력의 첫 요청은 모델명 외에 같았다. 양 모델 모두 NAT 도구 호출을 수행했지만 새 모델의 무오류·유효 제출 2/2 조건에는 못 미쳤다.

## 영상과 그래프에서 확인한 것

평가에 쓰지 않는 합성 이미지 한 장에서 도형·색·위치 세 개를 모두 맞혔다. [이미지와 응답](../evals/results/nemotron_endpoint_bottlenecks_20261016_v3/synthetic_preflight.json)은 이미지 입력 가능성의 근거다. 이 호출은 정식 영상 평가와 구분한다.

정식 B4에서는 평가 밖 클립으로 입력 가능성을 확인한 뒤, 등록된 정책 18개의 프레임을 여섯 장씩 제공했다. 응답은 걷기·제자리·넘어짐을 각각 `yes/no/unclear`로 기록했다. 정상 정책은 `walking=yes`, 실패 정책은 `walking=no`일 때 고정 평가 라벨과 대응한다고 정의했다.

- 정상 정책: 7/7 대응
- 실패 정책: 10/11 대응
- 전체: 17/18 대응, 응답 형식 18/18 유효
- 사전등록 하한: 전체 16/18, 정상 6/7, 실패 10/11 이상

| 고정 평가의 정책 분류 | `walking=yes` | `walking=no` | `walking=unclear` |
|---|---:|---:|---:|
| 정상 7개 | 7 | 0 | 0 |
| 실패 11개 | 1 | 10 | 0 |

유일한 불일치는 `motor_before`였다. 고정 평가에서는 실패 정책이지만 프레임 관찰은 걷기로 답했다. 고정 평가 라벨은 명령 추종 성능을 판정한 값이며, 클립에 보이는 행동의 정답 라벨은 아니다. **화면에 걷는 모습이 보여도 회복을 뜻하지 않는다.** 영상 관찰은 보조 근거로만 남기며 교정 승인·회복 결정에는 사용하지 않는다.

같은 학습 곡선 그림에 질문 두 개를 제시한 응답은 모두 형식상 유효했다. 끝점 비교에는 정상 곡선의 추종 보상이 높고 속도 오차가 낮다고 답했고, 결함 곡선의 추종 보상 개선·속도 오차 감소에는 모두 `no`라고 답했다. 이 두 질문은 그래프 입력 가능성 확인이며 별도의 정확도 점수나 B4 해결 조건에 포함하지 않았다.

## 요청 모델명과 반환 모델명

| 구분 | 식별자 |
|---|---|
| 기존 요청 및 반환 | `nvidia/nemotron-3-super-120b-a12b` |
| 새 요청 | `nvidia/nemotron-3.5-super-vl-120b-a12b` |
| 새 요청에서 관측한 반환 | `private/nvidia/nemotron-3.5-super-120b-a12b` |

NVIDIA는 2026-10-15에 새 VL 모델을 공개했으며 공식 모델 카드와 API 문서는 이미지·영상 입력과 도구 호출을 설명한다. [NVIDIA 발표](https://blogs.nvidia.com/blog/nemotron-3-5-super-vl/), [모델 카드](https://build.nvidia.com/nvidia/nemotron-3.5-super-vl-120b-a12b/modelcard), [API 문서](https://docs.api.nvidia.com/nim/reference/nvidia-nemotron-3_5-super-vl-120b-a12b-infer).

실제 반환 ID에는 `vl`이 없었다. 공식 문서에서 이 반환 ID와 요청 ID의 대응을 확인하지 못했다. 따라서 비교 단위는 공식 API에 요청한 경로이며, 서비스된 가중치의 동일성을 확정하지 않는다. 원시 반환 ID를 보존하고 새 판에 등록한 정확한 두 ID만 검증용 표현에서 허용했다. 이 정규화는 모델의 공식 별칭을 입증하는 절차가 아니다.

v1은 미실행으로 보존했다. v2의 첫 응답은 모델 ID 불일치로 `call_error`로 남겼고 소급 채점하지 않았다. 이 응답과 추가 합성 이미지 확인 뒤 v3의 반환 ID 계약을 등록하고 새 호출로 비교했다.

## 회복 시연에 연결한 영상 보조 관찰

새 Go2 보상 결함 seed 2080에서 진단·검사·교정·재학습 고리와 영상 관찰을 연결했다. 기본 시연은 `recovered`, `demo_success=true`였고 완료 조건 12개를 모두 충족했다. 정상·결함 정책의 고정 평가 직후와 교정 재학습(seed 3080)의 고정 평가 직후에 같은 checkpoint를 Play로 실행하고, 정책마다 프레임 여섯 장을 새 VL 요청 경로에 보냈다. [공개 결과](../evals/results/vl_aux_demo_public_s2080_20261016/summary.json).

| 정책 | 고정 평가 | walking | in_place | falling | 실제 입력 프레임 예시 |
|---|---|---|---|---|---|
| 정상 seed 2080 | healthy | yes | no | no | [정상](../evals/results/vl_aux_demo_public_s2080_20261016/frames/clip1/frame_03.jpg) |
| 보상 결함 seed 2080 | unhealthy | no | yes | no | [결함](../evals/results/vl_aux_demo_public_s2080_20261016/frames/clip2/frame_03.jpg) |
| 교정 후 재학습 seed 3080 | healthy | yes | no | no | [교정](../evals/results/vl_aux_demo_public_s2080_20261016/frames/clip3/frame_03.jpg) |

세 관찰 모두 형식상 유효했고, B4의 대응 정의(healthy면 walking=yes, unhealthy면 walking=no)로 3/3 대응했다. 이 수치는 위의 18개 영상 개발 측정과 합산하지 않는다. 고정 평가의 추종 성능 라벨과 별도 Play의 행동 묘사를 나란히 기록한 것이며, 세 프레임 묶음으로 영상 판독 정확도를 추정하지 않는다.

기존 텍스트 모델이 진단과 교정 결정에 각각 한 번 호출됐고 VL 관찰은 세 번 호출됐다. 총 5/16요청이며 재시도는 없었다. 영상 결과는 별도 기록에 `used_for_decision=false`로 저장했다. 진단·검사 선택·교정 승인·회복 판정의 입력으로 사용하지 않았다. **이 실행에서 회복은 고정 평가가 판정했고, VL은 정상·결함·교정 정책의 화면 관찰을 덧붙였다.**

[반환 모델 ID 기록](../evals/results/vl_aux_demo_public_s2080_20261016/provider_identity.json)은 요청명과 실제 반환명을 함께 보존한다. 공개 요약의 시간은 결정 호출의 기록값과 관찰 wrapper의 측정값으로 범위가 다르므로, `combined`를 동일 경계의 지연 시간이나 전체 실험 시간으로 해석하지 않는다.

설계자는 기존 F1 시연과 B4 관찰 결과를 본 뒤 연결 기능을 만들었다. [새 사전등록](../bench/protocols/vl_aux_demo_v1/e2e_demo_v4_f1.json)을 커밋 `110720c2b0188d48e39bbc8cdbc90a3d88fcc6bb`에서 고정하고 새 seed로 실행했다. Play는 고정 평가 실행 자체의 녹화가 아니라 동일 checkpoint의 별도 실행이다. 공개 결과에는 관찰에 사용한 프레임 18개와 원본 결합 해시를 포함한다.

## 적용 범위

기존 진단·교정 결정의 기본 모델은 유지한다. 새 요청 경로는 시연의 보조 영상 관찰로 연결했으며, 관찰 결과와 고정 평가 판정을 나란히 기록한다. 관찰만으로 회복 상태를 바꾸지 않는다.

모델 외 구성은 변경하지 않았다. 설치된 NAT는 확인한 안정 릴리스 [1.9.0](https://github.com/NVIDIA/NeMo-Agent-Toolkit/releases/tag/v1.9.0)과 같았다. [Isaac Sim 6.2 다운로드 문서](https://docs.isaacsim.omniverse.nvidia.com/latest/installation/download.html)와 [Isaac Lab 릴리스](https://github.com/isaac-sim/IsaacLab/releases)는 별도 호환성 검토 대상으로 남긴다. 기존 Sim 4.5·Lab 2.1.1 환경의 체크포인트와 평가를 유지하려면 새 버전의 기준선·물리 동작·기록기 회귀를 별도 실험으로 확인해야 한다. hosted API 응답의 모델명으로 설치형 NIM 버전을 추정하지 않는다.

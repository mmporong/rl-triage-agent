# Brev 통합 실행 기록

`active_20261011_v3_eula`는 기존 Brev 인스턴스에서 실제 Isaac 검사를 실행한 통합 기록이다. 이미 본 seed 2027 입력을 사용했다. 등록한 모델·고정 순서 규칙·저비용 규칙의 24개 실행 모두 종료 기록을 남겼지만, 후반에 모델 worker와 원격 전송이 실패했다. **전체 성능 비교는 수용하지 않는다.**

실행 전에 동결한 소스는 `272e91e790523930a49047eb54eb4ed5bb62c5b3`이며, [프로토콜](../bench/protocols/active_diagnosis_v3_eula.json)의 LF SHA-256은 `005b1b390b57f5ad7d1a8a49ddd276767cdbba83a0a7666e20e636fca4098a30`이다. 등록한 소스 16개의 해시는 실행 소스와 일치한다. 실패한 결과는 수정하지 않고 보존했다.

## 완료 기록과 검증

| 실행 방식 | 종료 기록 | 진단 완료 | 보류 | 성공한 검사 receipt | 유효한 사례 감사 | Isaac launcher 시간 | simulator steps |
|---|---:|---:|---:|---:|---:|---:|---:|
| 모델 | 8 | 0 | 8 | 3 | 8/8 | 47.0초 | 179,200 |
| 고정 순서 규칙 | 8 | 2 | 6 | 4 | 2/8 | 68.6초 | 256,000 |
| 저비용 규칙 | 8 | 1 | 7 | 3 | 1/8 | 22.9초 | 0 |

표는 [전체 상태 기록](../evals/results/active_20261011_v3_eula/cohort_status.json)과 [모델 감사](../evals/results/active_20261011_v3_eula/audit.json), [고정 순서 감사](../evals/results/active_20261011_v3_eula_fixed/audit.json), [저비용 감사](../evals/results/active_20261011_v3_eula_cheap/audit.json)에서 계산했다. 시간은 성공한 검사의 launcher 벽시계 기록이며 GPU 장치의 실제 점유 시간은 미측정이다. 검사 종류와 완료 범위가 달라 이 합계로 절감률을 계산하지 않는다.

감사 통과는 남겨진 기록의 일관성을 뜻한다. 모델의 원인 판단이 맞거나 유용하다는 뜻은 아니다. 모델 8건은 유효한 보류 1건, 최신 측정 인용 검증 실패 1건, 초기 worker 실패 6건으로 나뉜다. 두 규칙 방식의 전체 감사는 통과하지 못했다. 비공개 정답을 이용한 비교 채점은 실행하지 않았다.

## 첫 사례에서 확인한 동작

[모델 h01 기록](../evals/results/active_20261011_v3_eula/cases/h01_s2027/result.json)은 에피소드 종료 검사 `P_episode`와 노이즈 검사 `P_noise`를 골랐다. 두 Isaac 실행은 exit 0과 종료 정리를 기록했고, 128,000 simulator steps와 launcher 시간 36.5초를 사용했다. 모델 호출은 5회, 입력 15,201 tokens, 출력 804 tokens였다.

측정값을 받은 판단과 최신 결과를 가린 대조 호출의 순위는 모두 유지됐다. 따라서 이 사례는 **검사 때문에 판단이 바뀌었다는 증거가 아니다.** 두 규칙 방식의 같은 사례 기록도 감사에 통과했지만, 이 한 사례로 전체 성능을 비교하지 않는다. 정책 회복도 이 실행에서 측정하지 않았다.

## 실패와 남은 제약

모델 h02는 검사 뒤 최신 receipt의 측정값을 인용하지 못했다. 이 의미 검증 실패는 재시도 대상에 넣지 않는다. h03 이후 모델은 provider 요청 관측 없이 worker artifact가 없어 보류됐고, 규칙 실행도 Brev backend 오류로 중단됐다. 당시 worker의 stdout·stderr를 하네스가 보존하지 않아 원본 오류 문구는 복구할 수 없다.

후속 로컬 진단에서 최소 WSL 명령 `/bin/true`도 `Wsl/Service/0x80072747` 소켓·버퍼 부족 오류로 실패했다. 이는 현재 WSL 진입 장애를 확인한 것이다. 코호트 당시 각 worker의 stderr를 인증하거나 어떤 호출이 자원 누적을 만들었는지 증명하지 않는다.

후속 실행은 전송 경로의 상태 검사부터 통과해야 하며, 필요한 소스·프로토콜 변경을 커밋한 뒤 새 tag를 사용한다. 기존 유효한 결과와 의미 검증 실패는 보존한다. 이 기록으로 정확도·일반화·진단 우위·GPU 절감을 주장하지 않는다.

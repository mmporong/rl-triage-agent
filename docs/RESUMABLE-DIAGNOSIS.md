# 모델 판단 장애 뒤 재개하는 PPO 진단 고리

이 판은 API 장애가 발생해도 완료된 학습·평가·검사 기록을 보존하고, 응답이 저장된 판단만 같은 원장에서 재개한다. PPO 계산 오류를 처음 진단할 때 모델이 반환할 항목은 `action`, `probe`, `fact_ids` 세 개다. 범주 순위·검사 기대값·근거 수치는 호스트가 기존 등록 표와 입력에서 채운다.

이전 PPO 종단 실행에서는 기대값과 범주 순위가 계약을 어겨 검사를 시작하지 못했다. Brev의 등록 보상 결함 실행은 두 번째 판단의 HTTP 500 뒤 HOLD로 끝났다. 이 두 결과를 본 뒤 만든 기능이며, 이전 실행의 최종 판정은 유지한다. 이미 관찰한 계산 오류에서 개발한 판이므로 처음 보는 결함에 대한 대응 성능으로 해석하지 않는다.

## 판단과 실행의 상태

| 저장 상태 | 다음 동작 |
| --- | --- |
| 유효한 검사 선택 | 승인 뒤 해당 검사를 실행 |
| 완료된 일시적 인프라 오류 | `paused_infra`, 저장된 시각에서 30초 이후 한 번 재시도 |
| 예약은 있지만 저장된 응답이 없음 | `blocked_pending`, 자동 재전송 금지 |
| 학습·검사 시작 뒤 완료 증거 없음 | `blocked_stage_unknown`, 부분 실행을 자동 반복하지 않음 |
| 고정 피드백 뒤에도 모델 응답 무효 | terminal HOLD, 등록 규칙으로 바꾸지 않음 |
| 기존 완료 또는 HOLD | 같은 결과를 반환하며 새 API·GPU 요청 없음 |

완료 단계에는 체크포인트·텔레메트리·산출물 SHA를 결합한다. 재개할 때 소스 commit의 조상 관계와 결합 파일 blob, 프로토콜, 입력 snapshot, 첫 메시지, 요청 인자를 다시 확인한다. 결합이나 완료 산출물이 달라지면 실행하지 않는다. 같은 실행의 동시 controller와 판단 요청도 거부한다.

API 요청은 보내기 전에 예약하고 응답 저장 뒤 receipt를 연결한다. 한 대화에는 인프라 재시도 한 번과 고정 피드백 한 번을 포함해 최대 세 번 호출할 수 있다. 원장의 전체 상한은 20회다. 저장된 응답을 재생하는 동작은 API 호출로 세지 않는다. GPU 단계와 API 응답이 모두 없는 것처럼 처리해서 재실행하는 경로는 두지 않았다.

## 검사 선택과 교정의 주체

모델은 첫 검사와 근거 ID를 선택한다. 이후 검사 선택·가설 제거·확정은 기존 `C.advance` 등록 규칙이 수행한다. `P_torque` 이상만으로 actuator를 확정하지 않으며, 갱신 횟수 정상과 gradient 계산 이상을 별도로 기록한다.

근거 ID 검증은 인용한 항목이 입력에 존재하는지 확인한다. 인용한 수치와 원인 사이의 관계는 후속 검사로 확인한다.

`optimizer_surrogate` 하나가 남고 `P_ppo_gradient`의 유효한 abnormal receipt가 있어야 ratio 복원 교정을 제안한다. 교정 선택 주체는 등록 규칙이다. 승인·소비 원장 뒤 새 정책을 300회 학습하고, 계산 복원 검사와 정상 정책을 기준으로 한 고정 평가 26조건을 모두 통과해야 회복으로 기록한다.

## 실행과 검증 범위

[사전등록](../bench/protocols/ppo_resumable_demo_v1.json)의 source seed는 2200, 교정 재학습 seed는 3200이다. 실행 직전에 기존 기록과 Isaac Lab 로그를 다시 확인하며, 사용 흔적이 있으면 seed를 자동 교체하지 않는다. 기존 seed 2165와 Brev seed 2196의 실행을 인수하지 않는다.

CPU 회귀는 실제 등록 검사·승인 원장과 가짜 학습 backend로 수행한다. HTTP 500 뒤 대기, 새 프로세스의 재개, 완료 응답 재생, 미완료 예약 차단, 산출물 변조 차단, 계산 오류 확정·교정·후속 평가 상태 전이를 확인한다. 이 검증은 실제 새 정책의 회복 결과가 아니다.

GPU 실행기는 기존 Windows Isaac Lab backend를 사용한다. PowerShell에서 다음 명령으로 실행하거나 같은 실행을 재개한다. 공용 GPU 임대를 취득하고 각 GPU 단계에서 기존 strict 입장 검사를 수행한다. `paused_infra`이면 저장된 `not_before` 이후 같은 명령을 사용하며, 다른 terminal 결과에서는 재시도하지 않는다.

```powershell
cd "$HOME/rl-triage-agent"
& ./bench/run_ppo_resumable_demo_v1.ps1 -Execute
```

구현은 [단계 controller](../evals/ppo_resumable_demo_v1.py), [판단 원장](../evals/model_decision_journal_v1.py), [세 필드 계약](../evals/ppo_selection_adapter_v1.py), [모델 worker](../evals/ppo_resumable_model_v1.py)로 나뉜다. 원장과 단계 기록은 실행별 새 폴더에만 쓴다.

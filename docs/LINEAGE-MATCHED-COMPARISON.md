# 같은 사례에서 비교한 진단 선택과 실행 실패

[원문 결합 분석](../evals/results/lineage_matched_analysis_20261101_v2/analysis.json)에서 Nemotron 3.5와 고정 순서는 각각 10사례 중 2사례의 원인을 확정했다. 보상 결함 두 사례에서 모델은 검사 2개, 고정 순서는 3개를 사용했다. 다만 모델과 고정 순서의 양쪽 측정이 모두 끝난 짝은 4사례이고, 이 중 2개는 정상 호스트 무개입이다. 전체 진단 성능의 우위는 이 자료로 판정하지 않는다.

이번 작업은 이미 공개된 개발 결과의 사후 분석이다. 새 모델 호출·GPU 검사·학습은 없으며 원래 30행의 HOLD와 unknown을 그대로 두었다. [보고 코드와 분석 명세](../bench/protocols/lineage_matched_analysis_20261101_v2.json)는 최종 보고서 생성 전에 커밋했지만, 이를 원데이터를 보기 전의 사전등록으로 표시하지 않는다.

## 같은 입력과 검사 권한

입력은 [원래 10사례×3정책 결과](../evals/results/lineage_diagnosis_dev_20261031_v1/manifest.json)와 [18정책 수집·고정 평가](../evals/results/lineage_source_fixed_dev_20261031_v1/summary.json)다. [배치 등록](../bench/protocols/lineage_comparison_20261031_v1.json)의 사례·seed·정책 순서, 체크포인트·텔레메트리 SHA, 같은 초기 view, 논리 검사 3회·요청 1200초 한도를 대조했다. 규칙과 모델에 다른 검사 권한을 주지 않았고, 정상 무개입은 모델 호출 전에 호스트 gate가 결정했다.

[분석기](../evals/lineage_matched_analysis_v1.py)는 30행·88관측·56개 NIM 파일의 상대경로와 SHA를 확인한다. 정상 종료를 주장하는 관측에는 완료 영수증·측정값·자식 종료/정리 증거가 있어야 한다. 양쪽 측정값으로 동결 판정을 재계산하고, 등록 후보의 축소 과정을 재생해 원인 확정과 HOLD를 대조한다. 측정값이나 outcome을 바꾼 뒤 SHA만 다시 만든 자료도 이 검증을 통과하지 못한다.

영상으로 검사 선택이 개선됐다는 개발 근거가 없어 원래 등록의 비교 방식은 수치 입력을 쓰는 세 가지였다. 계획의 네 번째 영상 arm은 보류 상태다. 세 방식 비교를 네 방식 비교나 영상 효과 측정으로 쓰지 않는다.

## 전 사례 결과

| 사례 / seed | 주입 범주 | 등록 순서 | 고정 실행 가능 순서 | Nemotron 3.5 |

| case-02 / 2302 | NONE | 정상 무개입(호스트) | 정상 무개입(호스트) | 정상 무개입(호스트) |

`실행 미확정`은 원래 결과의 `HOLD/probe_outcome_unknown`을 설명하는 분석 분류다. 그 행을 삭제하거나, 검사가 정상으로 끝났다고 채워 넣지 않았다. 물리·탐색 범주는 등록 교정 밖의 입력이지만, 측정이 끝나지 않은 행을 올바른 원인 확정이나 올바른 지원 밖 판정으로 세지 않았다. 복합 결함에서는 한 성분의 확정과 전체 원인 확정을 분리한다.

원래 원장에는 모든 행이 `complete`로 남아 있다. 이는 결과 기록이 끝났다는 뜻이다. 관측 중 26역할은 부모 예외가 있었고 probe 영수증이 없었으며, 1역할은 자식이 exit0·cleanup을 마친 뒤 부모 검증에서 `PermissionError`가 났다. 그 오류의 세부 원인은 원문만으로 확정하지 못한다. [원래 집계](../evals/results/lineage_diagnosis_dev_20261031_v1/summary.json)의 확정 건수와 HOLD는 바꾸지 않았다.

## 짝 비교와 불확실성

| 비교(왼쪽−오른쪽) | 양쪽 측정 완료 짝 | 확정 건수 승/패/동률 | exact sign 참고값 |
|---|---:|---:|---:|
| 모델−고정 순서 | 4/10 | 0 / 0 / 4 | 1.0 |
| 모델−등록 순서 | 5/10 | 2 / 0 / 3 | 0.5 |
| 고정 순서−등록 순서 | 5/10 | 2 / 0 / 3 | 0.5 |

표의 분모에는 정상 호스트 무개입 2사례가 포함된다. 이를 LLM의 정상 판별 정확도로 쓰지 않는다. 모델 형식 실패가 있는 입력은 실패 점수 0으로 유지하며, 좋은 성적을 만들기 위해 비교에서 제외하지 않는다. 이번 원문에서는 해당 형식 실패가 없었다.

exact sign 값은 불일치 짝의 승패 수에서 계산한 참고값이다. 유형과 seed를 고정해 만든 개발 자료이므로 무작위 표본·배정의 근거를 대신하지 않으며, 일반적 모델 우위나 통계적 유의성을 선언하는 데 쓰지 않는다.

미확정 행의 원인 확정 여부를 0 또는 1로 둘 때, 전체 10사례에서 모델−고정 순서의 확정 비율 차이는 **−50~+50%p**, 모델−등록 순서는 **−20~+70%p**까지 가능하다. 이는 누락 결과가 허용하는 범위이며 신뢰구간이 아니다. 방향을 정할 만큼 정보가 충분하지 않다.

양쪽이 같은 보상 원인을 확정한 case-03·04에서는 모델이 각각 2검사, 고정 순서가 각각 3검사를 썼다. 이 두 사례의 사후 조건부 비교에서 검사 부모 시간 차이는 평균 −138.890초, owned 자식 시간 차이는 −101.194초, 추가 모델 응답 시간은 +2.771초였다. 전체 진단 벽시계와 GPU 커널 시간을 측정한 값은 아니다. 전 사례의 성공/보류가 다르고 실행 실패도 있어 전체 속도 개선이나 비용 절감으로 환산하지 않는다.

## 종단 회복은 다른 분모로 기록

[종단 근거 목록](../evals/results/lineage_matched_analysis_20261101_v2/e2e-scope-inventory.json)은 다음 세 범위를 분리한다.

- 사전에 정한 case-03·07 × 등록 순서·모델 선택의 첫 교정 4행: 1행 회복, 3행 HOLD. 확인된 후보 1행만 300회 학습과 26조건 평가를 완료했다.
- seed 2307 개발 후속: 보상 교정 뒤 미회복이었고 두 번째 진단은 세 검사 후 HOLD였다. 이 기록은 원래 비교의 성공으로 바뀌지 않는다.
- 새 갱신 입력의 별도 seed 2311: 첫 교정 뒤 미회복, 갱신 검사로 예상 20회·실제 4회 확인, 두 번째 교정 후 회복. 추종 오차는 1.219→1.163→0.142m/s였다. 이 사례를 원래 10사례 비교에 추가하거나 case-07의 결과와 바꾸지 않는다.

현재 결론은 **두 보상 사례에서 검사 수 차이를 관찰했고, 전체 방식 간 우위는 미확정**이다. 원래 묶음의 결론은 여기서 보존한다. 누락을 메우거나 새로운 입력·모델로 비교할 때는 별도 등록과 분모를 사용한다.

## 재계산

```powershell
cd "$HOME/rl-triage-agent"
& ./.venv/Scripts/python.exe -B evals/lineage_matched_analysis_v1.py --export-root evals/results/lineage_diagnosis_dev_20261031_v1 --source-summary evals/results/lineage_source_fixed_dev_20261031_v1/summary.json --batch-protocol bench/protocols/lineage_comparison_20261031_v1.json --out "$HOME/rl-triage-matched-analysis-new.json"
```

출력 경로가 이미 있으면 덮어쓰지 않는다. 입력의 파일·역할·측정값·분류 결합이 맞지 않으면 결과를 생성하지 않는다.

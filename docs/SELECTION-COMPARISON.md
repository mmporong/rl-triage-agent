# 검사 선택 입력의 개발 측정

Nemotron 3.5 Super VL 요청 경로에서 고정한 과거 입력 여섯 건을 호출했다. 두 사례의 첫 epoch와 첫 검사 기록을 이미 본 뒤 만든 개발 측정이다. 이 실행은 모델 호출 계약과 입력 노출에 따른 선택 변화만 확인했으며, 새 학습·GPU 실행·검사는 수행하지 않았다.

## 실행 결과

최종 응답은 6/6건이 계약에 맞았다. HTTP 요청은 7회였고, 6회 성공과 500 오류 1회가 기록됐다. 오류 뒤 등록된 인프라 재시도 1회에서 유효 응답을 받았다. 대기 중인 요청과 시간 초과는 없었다.

사전등록한 엄격한 기준은 모든 HTTP 요청의 성공을 요구한다. 따라서 실행 상태는 `complete`지만 `runtime_verified=false`다. production 입력의 첫 시도 유효율 1/2는 모델 출력 형식 위반이 아니라 HTTP 500 오류에서 비롯됐다.

| 사례 | production 선택 | 전체 관찰 입력 | 마스킹 관찰 입력 | 선택 변화 |
|---|---|---|---|---|
| case 1 | `P_episode` | `HOLD` | `HOLD` | 없음 |
| case 2 | `P_episode` | `P_reward` | `P_reward` | 없음 |

두 노출 쌍 모두 최신 관찰 사실을 인용했지만, 전체 관찰과 마스킹 관찰에서 선택은 같았다. 이 결과는 최신 사실의 인용 여부를 보여줄 뿐 선택에 미친 인과 효과나 회복 성능을 입증하지 않는다. 보조 노출 입력은 실행 결정에 쓰지 않았다.

## 사용량과 결합

성공 응답 6회의 기록된 토큰은 입력 16,676개, 출력 319개, 합계 16,995개다. 실패 응답에는 사용량이 없어 전체 요청의 토큰 합계는 계산하지 않았다. 일곱 요청의 벽시계 시간 합계는 106.48190629208693초다.

[공개 요약](../evals/results/selection_runtime_v2_20261023/summary.json)은 실행 경계와 사용량을, [선택 기록](../evals/results/selection_runtime_v2_20261023/decisions.json)은 여섯 조건의 최종 선택을 담는다. [재현 결합](../evals/results/selection_runtime_v2_20261023/provenance.json)은 실험 커밋과 두 프로토콜, 원본 capsule 6개, 호출 기록 6개, HTTP 원장 7개의 해시를 보존한다. 공개 파일에는 사용자 경로, 비공개 경로, 계정 정보, 원시 프롬프트와 응답, API 키를 넣지 않았다.

이 측정은 selector 정책 네 가지의 종단 비교가 아니다. D3와 D4의 구현·성능 결과로 합산하지 않는다.

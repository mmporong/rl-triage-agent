# 변경 여러 개가 섞인 실패 학습에서 원인 변경을 확정하는 데 드는 재학습

이 문서의 수치는 `evals/build_d3_doc.py`가 사전등록 프로토콜(`bench/protocols/d3_experiment_v2.json`), 무해성 smoke 요약, 본실험 요약에서 만든다. 손으로 고치지 않는다.

## 질문

로봇 RL 엔지니어가 설정과 코드를 여러 군데 바꾼 뒤 학습했더니 정책이 무너졌다. 바뀐 것 중 무엇이 원인인지 확정하려면 결국 그 변경만 되돌리고 다시 학습해 봐야 한다. 이 실험은 그 확인 재학습이 몇 번 필요한지를 방법별로 센다.

- 실패한 학습 하나에 변경 8개가 섞여 있고, 그중 하나만 학습을 망가뜨린다.
- 같은 재학습 상한(8회)과 같은 확정 규칙 아래에서 다섯 방법을 비교한다.
- 범위: Go2 flat 4096 env × 300회, k = 8, 사전등록 사례 3건(+집계하지 않는 개발 사례 1건). 결함·무해 변경·probe는 같은 설계자가 만들었고(U1만 외부 원인 결함의 의미 이식), 진단 정확도·일반화·실제 프로젝트에서의 절감을 재지 않는다.

## 사례

Go2 flat, 4096 env × 300회 학습이다. 원인 변경의 위치는 결과를 보기 전에 문자열 seed 난수로 정했다(`random.Random('d3_experiment_v2:<사례>').randint(1, 8)`). 무해 7개(v2 목록)는 카탈로그 순서, 해로운 변경을 그 위치에 넣는다.

| 사례 | 학습 seed | 원인 변경 | 위치 | 집계 |
|---|---|---|---|---|
| D0 | 2026 | U1 | 1 / 8 | 개발 사례(집계하지 않음) |
| C1 | 2035 | U1 | 2 / 8 | 집계 |
| C2 | 2036 | F1 | 7 / 8 | 집계 |
| C3 | 2037 | F2 | 2 / 8 | 집계 |

원인 변경:

- U1: 보상 4항이 읽는 root 몸체 좌표 선·각속도가 0(관측은 그대로) 출처: https://github.com/Motphys/UniLab/commit/58ec02ea8b650e6b90db222188a770932d6b9676, https://github.com/Motphys/UniLab/pull/1254
- F1: 속도 추종 보상이 몸체 좌표 대신 월드 좌표 선속도를 씀
- F2: DC 모터 토크-속도 곡선의 속도 항 5배(낮은 관절 속도에서 토크 포화)

무해 변경(원인 변경과 같은 범주의 변경을 일부러 넣었다):

- H1(reward): flat_orientation_l2의 제곱을 torch.square 대신 같은 값의 곱으로 계산한다(같은 수식)
- H3(reward): feet_air_time이 읽는 발 체공 시간을 5.0 s에서 자른다(보행 체공 시간보다 훨씬 긴 경우에만 걸림)
- H4(actuator): Go2 DC 모터 effort_limit·saturation_effort 23.5 → 23.7
- H5(observation): 관절 속도 관측 노이즈 ±1.5 → ±1.2
- H6(logging): 보상 관리자 시작 표의 가중치 열을 유효숫자 4자리 문자열로 출력한다(학습 값과 무관)
- H7(optimizer): PPO entropy_coef 0.01 → 0.008
- S4(reward): action_rate_l2의 제곱을 torch.square 대신 같은 값의 곱으로 계산한다(같은 수식)

## 다섯 방법과 확정 규칙

확정 규칙: 변경 c 하나만 되돌린 재학습(전체 − {c})이 healthy일 때만 c를 확정한다(모든 방법 공통). 이 관측 없이 이름만 대면 확정이 아니다. 상한 8회 안에 확정하지 못하면 미확정이다.

| 기호 | 방법 | 정의 |
|---|---|---|
| B1 | 이분 탐색 | 후보의 앞쪽 절반을 되돌리고(나머지는 적용) healthy면 그 절반, 아니면 나머지 절반. 하나 남으면 단일 되돌리기로 확정 |
| B2 | 하나씩 되돌리기 | 사례 순서대로 단일 되돌리기 |
| B3 | probe 범주 규칙 | 동결 고리(probe_loop, 모든 범주 가설, FIXED_ORDER, 같은 판정 임계값)로 메커니즘 m을 확정하면 범주가 m인 변경을 사례 순서로 먼저, 나머지를 사례 순서로 단일 되돌리기. 고리가 확정하지 못하면 B1 |
| B4 | 모델 순위 | B3와 같은 텔레메트리 사실·probe 관측과 변경 diff 원문으로 모델 단일 호출이 낸 순위대로 단일 되돌리기 |
| B5 | 모델 순위(probe 없음) | B4에서 probe 관측만 뺀 절제 |

- 모델: `nvidia/nemotron-3-super-120b-a12b`, evals/d3_model_call.py(WSL, temperature 0, max_tokens 16384, reasoning_effort none, 사례·방법마다 단일 호출). evals/d3_agent.py: 라벨·diff·텔레메트리 사실(B4는 probe 관측 포함), 출력 ranking·reasons·uncertain, 검증 실패는 의미 재시도 없이 model_invalid.
- 비용: 확정까지 그 방법이 혼자 돌았을 때 질의한 서로 다른 확인 재학습 수. unresolved·model_invalid는 R=8로 센다. 같은 seed·같은 부분집합의 재학습은 한 번만 하고 결과를 방법끼리 같이 쓴다(같은 키는 한 번만 학습한다. 여러 방법이 같은 부분집합을 물으면 그 결과를 같이 쓴다. 실제 GPU는 질의 합집합만큼 든다).
- 재학습 승인: 사용자가 위임한 운영자 승인 또는 사람 승인(승인자 문자열 기록, 신원 인증 아님).

## 사전 예측과 결정적 기준선

결과를 보기 전에 계산한 결정적 방법의 확인 재학습 수다. 변경끼리 상호작용이 없고 검사가 원인 범주를 맞힌다고 가정했다.

| 사례 | B1 이분 탐색 | B2 하나씩 | B3 probe 범주 규칙 |
|---|---|---|---|
| C1 | 4 | 2 | 2 |
| C2 | 3 | 7 | 3 |
| C3 | 4 | 2 | 1 |
| 합 | 11 | 11 | 6 |

- 검사 예측(U1): P_episode·P_noise normal, P_reward abnormal → reward 확정(probe 3개). U1 종단 시연 seed 2040(4e13082)에서도 P_reward 한 번으로 reward가 확정됐다
- 검사 예측(F1): U1과 같은 경로로 reward 확정(probe 3개)
- 검사 예측(F2): P_reward normal로 reward 기각 → P_torque abnormal → actuator 확정(probe 4개)

## 우위로 말하는 조건

모델 순위(B4)가 결정적 기준선보다 재학습을 줄였다고 말하려면 다음을 모두 만족해야 한다.

- ① 유효 사례에서 B4 확인 재학습 합 < B1·B2·B3 합의 최소
- ② 어느 유효 사례에서도 B4 > B3 아님
- ③ B4 잘못된 확정 0, unresolved 0
- ④ 유효 사례 3개

결과는 네 가지 중 하나로만 쓴다.

| 결과 | 문구 |
|---|---|
| 재학습 감소(agent_fewer_retrains) | k = 8, 사전등록 사례 3건에서 변경 diff와 probe 관측으로 순위를 매긴 에이전트가 결정적 기준선보다 확인 재학습을 적게 써서 해로운 변경을 확정했다. 사례 수가 적어 일반화·통계적 우위의 근거가 아니다. |
| 우위 없음(no_advantage) | 이 설정에서 에이전트 순위는 결정적 기준선보다 확인 재학습을 줄이지 못했다. |
| 열세(agent_worse) | 에이전트 순위가 결정적 기준선보다 재학습을 더 쓰거나 틀린 변경을 확정했다. |
| 판정 없음(invalid) | 사례 성립 조건을 채우지 못해 방법 비교를 판정하지 않는다. |

## 이 실험이 말하지 않는 것

- 결함·무해 변경·검사를 같은 팀이 만들었다. U1만 다른 프레임워크에서 원인이 확정된 결함의 의미를 옮긴 것이다.
- 변경 8개, 사전등록 사례 3건이다. 변경 수가 다르거나 사례가 많아도 같은 결론이 나온다고 말하지 않고 통계 검정도 하지 않는다.
- 무해 변경 목록은 smoke v1 결과를 보고 한 번 바꿨다(위 절).
- 원인 변경의 위치는 난수로 정했다. 위치가 앞이면 하나씩 되돌리기가 유리하다.
- U1·F1의 diff에는 속도를 0으로 바꾸거나 좌표계를 바꾸는 줄이 보인다. 모델이 이런 흔한 버그 형태를 알아본 것인지 학습 신호를 읽은 것인지 이 실험으로 가를 수 없다.
- 재학습 캐시는 같은 seed·같은 코드의 학습이 체크포인트까지 같다는 가정에 기댄다. 개발 사례 D0에서 같은 부분집합의 두 학습 체크포인트 SHA가 같았다(대조 출처 smoke).
- 무해성 smoke v2는 무해 목록을 seed 2026, 2027에서만 확인했다. 집계 제외된 사례에서 무해 변경만 남긴 재학습이 밴드를 넘은 원인(특정 변경·변경 조합·seed 변동)은 이 실험으로 가르지 않는다.
- 하지 않는 주장: 에이전트가 더 정확하다, 일반화, 실제 PR·프로젝트에서의 절감, 통계적 유의, 다른 실험과 합친 분모, k ≠ 8에서도 성립, LLM 코드 리뷰가 사람보다 낫다, B5 결과를 probe 일반의 가치로 확대.

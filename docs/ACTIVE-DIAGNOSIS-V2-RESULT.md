# 판단 갱신 v2 실행 기록

등록한 8개 모델 사례의 기록 감사는 모두 통과했지만, 검사 결과 때문에 우선 가설이 바뀌었다는 기준은 0/8이다. 모델 실행은 1개가 종료 상태 `completed`, 7개가 HOLD다. 이미 본 seed 2027 입력의 통합 기록이며 정확도·일반화 평가가 아니다.

| 방식 | 사례 | 실행 종료 / HOLD | 모델 호출 | 실제 검사 | Isaac launcher 합계 | 환경 step |
|---|---:|---:|---:|---:|---:|---:|
| 모델 | 8 | 1 / 7 | 22 | 7 | 215.7초 | 384,000 |
| 고정 순서 | 8 | 8 / 0 | 0 | 15 | 782.5초 | 972,800 |
| 저렴한 판별 검사 우선 | 8 | 8 / 0 | 0 | 15 | 203.9초 | 0 |

실행 종료는 원인 확정이나 정답 일치를 뜻하지 않는다. HOLD 때문에 실행하지 않은 검사를 절감으로 세지 않는다. 서로 다른 완료 조건과 부하가 섞인 launcher 합계를 AI 우위나 GPU 절감으로 비교하지 않는다. 장치 연산 시간과 사람 검토 시간은 미측정이다.

모델 호출 총 입력 토큰은 63,319, 출력 토큰은 4,811이다. 관측을 가린 대조 호출과 거절 응답도 포함한 실험 총비용이다. 모델 worker의 응답 시간 합계는 48.413초이며, 제품 진단 한 번의 비용으로 옮겨 쓰지 않는다.

`h03_s2027`에서는 AI가 선택한 `P_episode`의 `timeout_ratio=0.05`를 받은 뒤 우선 가설이 `reward`에서 `termination`으로 바뀌었다. 그러나 같은 단계에서 최신 결과를 가린 새 호출도 `termination`으로 바꿨다. 결과를 인용한 순위 변경만으로 검사 결과의 기여를 인정할 수 없어 성공 장면에서 제외했다.

그 밖의 HOLD에는 실제 관측 뒤 동결 규칙과 맞지 않는 확정 제안, 초기 응답 계약 위반이 포함된다. 실제 판단과 가림 대조의 오류는 분리돼 유효한 실제 호출을 막지 않는다. 다른 GPU 작업이 있을 때는 작업 종료를 기다렸으며, 다른 세션을 종료하지 않았다.

이번 결과는 모델의 검사 선택·실제 측정·새 판단·가림 대조를 기록하는 실행 고리가 동작했다는 근거다. 유효한 기록과 유용한 진단은 별개다. 새 실행에서는 공개 판정 규칙 설명과 원격 실행 결속을 사전등록하되, 기존 probe·예산·임계값·성공 기준은 유지한다.

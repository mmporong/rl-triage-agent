# V17 r2: CPU 사전확인과 학습 seed 소비의 구분

V17의 첫 등록은 GPU·API 실행 전에 seed 검사에서 중단됐다. 검사기는 앞서 SDK 시작 직전에서 차단한 CPU 사전확인 결과의 `training_seed=6666`을 실제 학습 소비로 분류했다. 기존 V17 등록과 실패 영수증은 보존하고 이 판으로 이어간다. 이 실패의 부모 경과 243.884642초와 현재 프로세스 CPU 95.1875초도 준비 비용에 포함한다.

학습 seed 6666·6667, 입력·교정·300회 학습·회복 기준·실행 순서·완료 효과 7개와 완료 학습 1개 재사용·원래 HOLD 1개·신규 SDK 예상 15/상한 16·누적 상한 65·API 0은 V17을 유지한다. 기존 완료 학습은 다시 실행하지 않는다. 행동 평가 결과를 보고 고르는 재시도가 아니다.

## 분류와 거부 조건

새 seed 검사는 기존 전체 기록·Isaac Lab 로그 검사를 유지한다. 제외 provider 폴더는 기존과 같이 열거 전에 가지치기한다. 추가로 공개 등록 표의 SHA와 결합된 CPU 사전확인 결과 파일 한 개만 실제 학습 소비 후보에서 분리한다. 폴더 전체, 같은 seed의 다른 결과, 실행 로그를 검사에서 빼지 않는다.

CPU 기록은 알려진 schema, 성공한 전체 사전확인 항목, SDK·GPU 조회·API 0, 실행 전 차단 1회, 전후 소스·HEAD 일치, 원문 참조 SHA와 owned 실행이 시작되지 않은 증거를 함께 검증한다. 필드 하나의 `SDK=0` 선언만으로 제외하지 않는다. 완료 학습이나 시작된 프로세스 증거, 원문 변조, 누락된 참조, 다른 실행 기록 또는 실제 로그의 seed 충돌은 거부한다.

공개 등록 표는 논리 ID와 원문 SHA·seed·사전확인 helper SHA를 고정한다. 실제 파일 위치는 비공개 준비 manifest에 둔다. 분류 영수증에는 제외한 개별 파일과 검증 근거를 남기며, seed의 미사용 범위는 기존 로컬 조사 범위를 넘겨 주장하지 않는다.

## 실행과 보고

새 source와 r2 등록을 커밋한 뒤 실제 입력의 CPU 소비 확인을 수행하고 공용 lease로 실행한다. GPU 입장 기준·승인·단회 소비·교정 registry·kernel 경계는 바꾸지 않는다. 진단 재요청도 없다. 기존 V16의 unknown과 V17 준비 실패를 회복 결과로 바꾸지 않는다.

새 실행의 결과가 미회복이거나 방식별 차이가 없어도 그대로 보고한다. 이전 비용과 새 비용은 한 번만 합치고, 전체 경과·CPU·청구·장치 에너지의 미관측 항목은 unknown으로 보존한다. CPU 사전확인과 실제 학습·고정 평가의 완료를 구분한다.

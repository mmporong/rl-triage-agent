# 이어 실행의 CPU 상한 정산 사전 정정

V17 r2의 GPU 실행 전에 정산기 V1이 CPU checkpoint·telemetry의 등록 상한 각 8회를 실제 기대 횟수와 혼동한 것을 확인했다. 기존 모터 실행의 실제 자원 영수증은 두 CPU 작업 모두 0회이며, 완료 학습을 가져오는 모터의 fixed-only 경로도 두 작업을 새로 실행하지 않는다. 미시작 epoch 7개가 각 작업을 한 번씩 실행하는 구조다.

새 읽기 전용 정산기 V2는 관측 횟수를 그대로 보고하고 각 8회 이하인지 검증한다. 실제 새 실행은 checkpoint 7회·telemetry 7회가 예상된다. 9회는 거부한다. 기존 정산기 V1, 공개 등록, 실행 입력, source closure와 원문은 보존한다. V1의 이 비교 조건을 실제 정산에 사용하지 않는다.

이 정정은 `registered_recovery_comparison_s2664_s2667_20261105_v17_r2.json`(SHA `a8db2c666b390df191b7ca04e5ef718b9536c307057e0c71dc3fd441e9928dbd`)의 상한을 바꾸지 않는다. 진단·승인·교정·학습·평가·실행 순서·SDK 예상 15/상한 16·누적 상한 65·API 0·회복 기준도 그대로다. 정산기 V2와 이 문서를 실제 GPU 실행 전에 커밋하며, 실행 소스 결합과 사후 정산 소스 결합은 구분한다.

부모 경과 안의 owned 구간, 이전 효과·완료 학습, device 표본은 한 번만 센다. CPU 횟수, CPU owned wall, 측정하지 않은 CPU process 시간도 서로 바꾸지 않는다. 음성 결과나 미관측 비용은 그대로 남긴다.

# Brev 영상 자료 수집 사전등록 v2

이 판은 새 Go2 정상·보상 결함 정책의 동기화 영상 자료를 준비한다.
모델의 검사 선택이나 교정 효과는 이 수집 결과만으로 판정하지 않는다.

## 결합과 실행 순서

- 소스: `vision_brev_source_20261025_v2.json`.
- 렌더: `vision_brev_render_20261025_v3.json`.
- 실행 전 점검: `vision_brev_preflight_20261025_v2.json`.
- 이전 v1 초안 세 파일은 커밋·실행 없이 보존했다. 완료 자료의 오프라인 회수를 보완한 소스 해시로 이 판을 등록한다.
- 위 파일과 결합 코드를 커밋한 뒤 실행한다. source anchor의 조상 관계와 결합 파일의 내용을 대조한다.
- 소유 VM 한 대에서 기존 환경 검사 → 별도 seed 20회 학습·렌더 점검 → 정상·결함 학습 → 고정 평가 → Play 녹화 → checkpoint별 렌더 확인 순서로 진행한다.

## 결과 전 예측과 판정

1. 실행 전 점검은 정상 정책 20회 학습과 A→B→A 렌더 검사가 모두 유효할 것으로 예상한다.
   실제 갱신 수·환경 수·종료·산출물 해시·원본 동기화 증거가 일치하고 첫 소스 action의 시간·예산이 남아 있을 때만 수집을 시작한다.
   이 점검에서 `model_use_ready`는 항상 false다.
2. source seed 2200·2201에서 정상 정책은 기존 고정 평가 밴드를 통과하고 F1 정책은 이동 추종 기준을 통과하지 못할 것으로 예상한다.
   밴드·task·평가 조건은 JSON에 결합한 기존 판을 사용한다. 예측과 다르면 그 결과를 보존하며 성공 사례를 얻기 위한 seed 교체는 하지 않는다.
3. 각 정책의 Play 영상·명령·운동·simulation time은 같은 실행에서 수집한다. 실제 녹화 및 별도 렌더 검사와 환경·checkpoint·소스 결합이 모두 유효한 자료만 후속 입력 후보로 내보낸다.
   실패한 동기화 자료는 모델 입력에 사용하지 않는다.
4. 동일 정책에서 자른 두 구간은 독립 학습 사례로 세지 않는다. 학습 계보는 source seed 두 개이며 영상 구간 수와 구분해 보고한다.
5. 정상 대조 실패 또는 결함 정책의 실패 부재는 해당 seed의 종단 시연 준비 미충족으로 기록한다.
   모델 비교·교정·회복의 결과로 대체 해석하지 않으며 후속 사전등록의 입장 조건을 다시 확인한다.

## 고정 자원과 중단 조건

- 핵심 학습 계획: 두 seed의 NONE·F1·CORRECTED 각 300회, 환경 4,096개, 총 여섯 건.
  이번 소스 단계는 NONE·F1 네 건만 실행한다. CORRECTED 두 건은 후속 고리의 유효 교정 승인 뒤에만 실행한다.
- 별도 실행 전 점검: seed 2202, NONE 20회. 실제 실행 전 로컬·원격 기록에서 세 seed의 미사용 상태를 재검사한다.
- 이번 소유 VM compute 상한은 20 USD다. JSON의 시간당 견적과 실제 시작 요청부터의 경과 시간으로 준비·대기·회수 시간을 포함해 계산한다. 저장소 과금과 공급자 청구액은 별도다.
- 다음 단계의 최대 시간·비용을 예약할 수 없거나 GPU가 점유 중이면 새 실행을 보내지 않는다.
- 완료 cache는 원본 해시와 종료 증거로 회수하며, 실행 여부가 불명확한 pending은 자동 재전송하지 않는다.
- 단계별 산출물을 로컬로 회수해 해시를 확인하고, 소유 자원의 식별자와 현재 점유를 다시 확인한 뒤 해당 VM을 Stop한다.

## 고정 결과 문구

| 관측 | 사용할 문구 |
|---|---|
| 정상 통과·F1 실패·녹화 및 렌더 검증 통과 | 새 source seed 두 조건의 동기화 자료를 확보했다. 모델의 검사 선택·교정 효과는 후속 평가 대상이다. |
| 정상 통과, F1도 통과 | 해당 seed에서 등록 결함의 실패가 확인되지 않았다. 이 결과를 회복 시연의 실패 정책으로 사용하지 않는다. |
| 정상 대조 미통과 | 해당 seed의 정상 대조가 고정 평가를 통과하지 못해 종단 시연 준비 조건을 충족하지 못했다. |
| 동기화·결합·종료 증거 불충족 | 수집 자료가 입력 계약을 충족하지 못해 모델 입력 사용을 보류했다. |
| 시간·비용·자원 조건 미충족 | 등록한 자원 조건을 충족하지 못해 새 실행을 보류했다. 완료 자료와 소비 기록은 보존했다. |

이미 본 보상 결함과 기존 실행 결과를 바탕으로 설계한 수집 절차다.
새 seed에서 얻은 결과도 등록한 결함·환경·조건의 확인으로 보고하며, 처음 보는 결함에 대한 대응으로 표현하지 않는다.

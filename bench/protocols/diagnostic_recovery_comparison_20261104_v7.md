# 교정 비교 v7: 기본 데스크톱 공유 GPU 입장 규칙 복원

## 변경 사유와 보존

- v6의 입력 준비와 완료 효과 가져오기는 통과했으나 새 학습·고정 평가·모델 호출은 시작되지 않았다. 실행 전 입장 a01~a14는 모두 요청 소비 전에 거부됐다. 원문·대기·사전등록과 CPU 비용은 보존한다.
- 실제 a08의 기반 `desktop_shared_recording_v1` 판정은 추가 데스크톱 네 종류의 미등록 사유만 남겼다. ChatGPT·원격화면의3D와 Chrome의 VideoDecode는 기반 판이 허용한 그래픽 엔진이었다. 추가한 quiet profile은 전체 사용률1%·활성엔진 없음도 요구해 기반 공유 규칙보다 엄격했다.
- v7은 이 추가 유휴 제약을 사용하지 않는 별도 opt-in 판이다. v6의1% 정책이나 결과를 고치지 않는다. 학습·판정 기준을 통과시키기 위한 변경으로 해석하지 않는다.

## 새 입장 계약

- `registered_desktop_shared_baseline_v1`은 기반 공유 판의 등록 그래픽 엔진3D·Copy·VideoDecode·VideoEncode와 프로세스 검증을 유지한다. `gpu_exclusive=false`, `performance_measurement=false`다.
- 기존 production reader가 같은 fresh XML/CIM과 live lease를 검증한다. 기존에 추가한 데스크톱 네 종류도 path·basename·CIM Name·명령어·유형의 신원 검증을 통과해야 한다. 이름만으로 허용하지 않는다.
- 원 판이 허용한 그래픽 사용은 관측값으로 남긴다. 사용률은 정수0~100, 엔진의 PID·이름·종류·physical GPU·범위를 확인한다. 자료 부족·미등록 엔진·미확인 PID·신원 불일치·계산/Isaac 작업·메모리4096MiB 이상·lease 오류·기타 기반 거부는 계속 차단한다.
- 추가 quiet 제약 두 사유를 구별한다. 새로 등록한 네 GUI의 활성 엔진은 같은 관측의 신원·PID·이름·허용 종류·physical GPU가 모두 확인된 정확한 미등록 엔진 사유에만 예외를 둔다. 그 외 기반 거부를 제거하거나 invalid 자료를 quiet 사유로 취급하지 않는다. 운영 scope는 무인자이며 fixture callback을 받지 않는다.

## 같은 비교와 비용 해석

- v6의 원천·모델 판단·교정·300 update·seed·밴드·16arm·완료 기준을 그대로 유지한다. 완료 효과1건과 완료 학습1건은 동일 proof로 가져온다. 새 SDK 상한29·예상27·CPU checkpoint16·telemetry16·owned61·API0이다.
- 첫 효과와 static 학습을 다시 실행하지 않으며, 같은 checkpoint 바이트를 다른 방식의 평가로 바꾸지 않는다. 대기 중의 v6 요청은 새 권한이나 완료 효과로 가져오지 않는다.
- v7은 공유 데스크톱에서의 관측 비용 비교다. 전체 사용률·장치 전력·VRAM·허용된 그래픽 활동을 보존하고 계산 작업과 구분한다. 장치 energy를 SDK 전용 energy로 바꾸지 않는다.
- 입력과 알고리즘은 같은 조건으로 비교하되 데스크톱 부하·cache·인프라 재개가 통제된 독점 성능 실험이라고 주장하지 않는다. 방식별 실제 요청·검사·학습·평가·활성 명령·전체 관측 구간을 기술 통계로 보고하며 시간 차이를 인과적 속도 우위로 해석하지 않는다.
- 이전 실패·입장 대기·준비·기존 실행·새 dispatch와 전체 effect 비용을 별도 scope로 남긴다. 모터/optimizer 불변식, 회복 판정 밴드, 관측 비용 상한은 바꾸지 않는다. 미기록 값은 null이며 긍정·차이 없음·악화·판정 불가를 그대로 남긴다.

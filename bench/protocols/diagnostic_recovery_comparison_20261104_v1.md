# 원인 검사·교정 고리와 네 선택 방식의 비교 사전등록

이 문서는 원천 수집이 진행되는 동안 새 코호트의 행동 수치·라벨을 열지 않고 작성했다. 실제 비교 전에 코드와 함께 커밋하고, 진단·교정 계획의 입력 SHA에 결합한다. 단독 실행 승인으로 쓰지 않는다. 도구와 판정기는 기존 개발 사례를 본 뒤 설계했다. 새 seed 확인은 같은 로봇·등록 결함 안에서의 확인이며, 처음 보는 결함에 대한 일반화 시험이 아니다.

## 비교 단위와 입력

- 로봇·태스크: Go2, `Isaac-Velocity-Flat-Unitree-Go2-v0`.
- 등록된 원천 수집: `lineage_source_collection_s2660_s2669_20261104_v1.json`, 원천 20학습·20고정평가, 모델 호출 0. 각 학습은 4096환경·300갱신이다.
- 진단 10사례: 정상 2660·2661, 보상 2662·2663, 모터 2664·2665, 보상+PPO epoch 복합 2666·2667, physics 2668·2669. 정상 독립 참조는 3660·3661이며 나머지는 등록된 같은 seed 정상 실행을 사용한다. 원천 구성은 [등록된 수집 프로토콜](lineage_source_collection_s2660_s2669_20261104_v1.json)의 cases가 정본이다.
- 원천 확보 비용은 공통 비용으로 한 번 보고한다. 이미 존재하는 checkpoint를 읽은 시간만을 학습 확보 비용으로 쓰지 않는다.
- 동일 case/reference·공개 사실·도구·판정·상한에서 고정 순서, 명시 규칙, 같은 모델 단일 계획, 관측 후 반복 판단을 비교한다. case별 순서는 회전 배치한다.
- 모델은 등록된 Nemotron 3.5 Super VL endpoint와 같은 sampling이다. 이 비교의 입력은 수치·텍스트다. 영상 이득이나 3 Super 대비 모델 개선 시험으로 부르지 않는다.

## 진단 예측과 판정

1. 모터 mapping 검사에서는 정상 대조와 등록 모터 변이가 구분될 것으로 예측한다. PPO 오류에서 토크 증상만으로 모터 원인을 확정하지 않는다.
2. 복합 사례의 epoch 오류는 실제 optimizer step·minibatch 수로 구분될 것으로 예측한다. surrogate 계산 오류의 양성 대조는 이미 본 개발 component 측정이며, 이 새 원천 코호트에는 surrogate 변이를 넣지 않았다. 새 runtime의 짧은 재현 검사이며 과거 checkpoint의 모든 갱신을 역추적한 증거가 아니다.
3. 노출 도구는 `P_actuator_mapping`, `P_optimizer_count`, `P_optimizer_gradient`다. 보상·physics는 이 도구 집합 밖이다. 검사 정상이나 HOLD를 그 원인의 진단 성공으로 합산하지 않는다. 복합 사례에서 epoch를 확인해도 보상 원인까지 확인했다고 쓰지 않는다.
4. 원천과 참조가 절대 보행 자격과 상대 band를 모두 통과하면 네 방식 모두 모델·검사 없이 호스트가 개입을 막는다. 모델의 정상 식별 성공으로 세지 않는다.
5. 참조 자격이 부족하거나 행동 묶음을 검증할 수 없으면 `hold_observation_unqualified`로 멈춘다. 이를 정상이나 원인 부재로 바꾸지 않는다.
6. 잘못 확정한 원인, 정상 입력의 검사 제안, host 차단, 미확정, 지원 밖, 기술 실패를 구분한다. 숨은 결함 표는 사후 채점에만 쓰며 승인·교정 선택에 전달하지 않는다.

진단은 사례당 최대 3검사, 전체 최대 120 Simulator 검사 실행과 모델 요청 40회를 허용한다. 의미 실패의 재요청과 대체 seed는 없다. 원천 실패 부재·기준 미달 사례도 계획 10사례와 제외·보류 사유를 함께 남기며 분모를 조용히 줄이지 않는다.

## 교정·후속 평가

진단 결과를 보기 전에 모터·복합 4사례 `case-05`∼`case-08`를 선택했다. 네 방식 모두 같은 원천·회복 방식·학습 예산·고정 평가를 사용한다. 총 계획 분모는 16 arm이다. 아래 surrogate 교정은 조건부 등록 템플릿이며, 이 코호트에서 그 양성 원천의 회복률을 측정하는 것은 아니다.

| 확인된 원인 | 등록 교정 | 회복 방식 | 갱신·seed |
|---|---|---|---|
| actuator | torque-speed 함수 복원 | 이어 학습 | 300 추가 갱신, 원천 seed |
| optimizer update count | configured epoch 복원 | 재학습 | 300갱신, 원천 seed+3000 |
| optimizer surrogate | clipped-surrogate 계산 복원 | 재학습 | 300갱신, 원천 seed+3000 |

- 지원되는 확인 원인과 유효 receipt가 있을 때만 별도 승인·소비 뒤 실행한다. 미확정·정상 gate·지원 밖은 새 학습을 시작하지 않는다.
- 예측: 복합 사례의 epoch 복원만으로는 남은 보상 결함이 수리되지 않아 미회복할 수 있다. 모터 이어 학습은 기존 개발 결과상 개선·미회복이 모두 가능하다. 같은 입력에서 선택 방식만으로 회복률이 달라질 것이라는 예측은 두지 않는다.
- epoch 교정 재학습은 원천의 등록 환경 조리법을 보존한다. 복합 사례의 world-frame 보상을 body-frame으로 함께 바꾸지 않으며, 모터 원천에 epoch 교정이 선택돼도 원래 모터 함수를 유지한다. 원천 manifest·환경 설정·SDK 3.10 컴파일 계약을 결합하고, 새 학습의 보상·모터 함수 지문과 저장된 보상 설정을 확인한다. 과거 학습의 보상 runtime 지문은 기록되지 않았으므로 조리법 출처와 새 runtime 관측을 구분한다. 자식 수와 학습 예산은 늘리지 않는다.
- `recovered`는 실제 새 checkpoint·교정 적용·실행 종료·동일 고정 평가와 참조 결합 및 절대·상대 행동 조건을 검증했을 때만 쓴다. 같은 정지 정책의 상대 비율 1은 회복 증거가 아니다.
- epoch·surrogate 교정의 첫 3갱신 기록을 동결 검사기로 다시 계산한다. 이는 교정 학습 초기 runtime 확인이며 최종 가중치나 이후 모든 갱신의 검사가 아니다.
- 교정 runtime 확인이 정상이고 절대 보행은 통과했지만 참조 상대 band만 미달하면 추가 교정을 만들지 않고 참조 점검으로 보낸다. 확인이 카탈로그 일부에 그치면 `reference_review_first`이며 미관측 구성요소 확인도 남긴다. 모든 필요한 확인이 정상인 경우의 `reference_review_only`와 구분하고, 참조가 원인이라는 인과 주장은 하지 않는다.
- 모터 readback만 있고 등록된 후속 mapping 관측이 없으면 해당 확인은 unknown/HOLD다. fixture 영수증이나 교정 전 검사를 새 정책 확인으로 재사용하지 않는다.
- 실패·unknown·HOLD와 그때까지의 비용도 남긴다. 다른 회복 방식이나 예산으로 결과를 본 뒤 바꾸지 않는다.

실행 상한은 교정 16회, Simulator 학습·평가 최대 32자식, CPU checkpoint 검사 최대 16자식, CPU 로그 추출 최대 16자식, owned 자식 합 최대 64개다. 회복당 부모 경과 상한은 5000초, 이 후속 단계의 모델 호출은 0이다. CPU 로그 추출은 기존 실행기의 별도 자식임을 확인해 등록 전에 포함했으며 학습·GPU 실행 수를 늘린 것이 아니다.

## 비용과 결과 문구

- 모든 계획 사례·arm을 보고한다. 같은 성공 endpoint끼리의 비용 비교는 전체 실패·HOLD·미실행 표와 함께 보조로 둔다. 반복 arm은 독립 학습 seed로 세지 않는다.
- 준비·출처 검증·API·Simulator 시작/검사·학습·평가·CPU checkpoint/로그 추출·실패/재개·전체 경과를 구분한다. SDK owned wall은 GPU kernel 실행 시간이 아니다.
- 장치 사용률·메모리·전력과 표본 범위를 기록한다. energy는 장치 전체 표본 적분이며 모델 서버나 프로세스 전력으로 옮기지 않는다. 표본 누락·지원 불가·대기 미측정은 null이다.
- 모델 예약·확인된 HTTP·토큰·요청/반환 모델명·종료 사유를 남긴다. provider GPU 시간·가격 근거·실청구를 확보하지 못하면 미확정이다. 모델 무호출의 요청·토큰 0과 청구 미확정은 구분한다.
- 캐시는 지우지 않는다. 앞선 원천·개발 실행의 cache가 남은 같은 호스트에서 순차 비교하며, 배치 순서와 부하를 보존한다. 사람 수동 진단 시간은 실측하지 않는다.
- 양성 차이: 같은 성공 기준과 원문 비용이 모두 확인된 해당 짝에서만 수치 차이를 적는다. 카탈로그·태스크 전체의 우월성으로 확장하지 않는다.
- 차이 없음·악화: 같은 결과에서 반복 판단의 시간·호출이 늘었거나 개선이 없으면 그 값과 분모를 그대로 적는다.
- 판정 불가: 성공 endpoint 부재, 비용·실행 증거 불완전, 기준 부적격이면 차이를 만들지 않고 이유와 unknown을 남긴다. 작은 표본의 기술 통계이며 통계적 우월·일반화·절감을 주장하지 않는다.

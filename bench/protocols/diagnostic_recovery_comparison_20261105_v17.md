# V17: 순서 균형 재측정의 학습 보존 이어 실행

## 사전 고정 범위

이미 본 개발 자료의 자원 재측정을 이어간다. V16의 결과·프로토콜·요청 원장은 수정하지 않는다. 새 seed 보류 평가나 새 진단 비교로 부르지 않는다. 모델 재요청과 API 사용 상한은 0이다.

V16은 등록 순서대로 7개 효과를 완료했으며 모두 미회복이었다. 여덟 번째 `case-06/fixed_sequence`는 교정 학습 300회와 체크포인트 저장을 마쳤다. 학습 종료 코드는 0, owned 정리는 true였다. 이후 고정 평가의 실행 전 GPU 입장 관측에서 `RetryAdmissionError`가 발생해 원래 요청은 unknown으로 종결됐다. 평가 Simulator는 시작되지 않았다. 원래 오류의 상세 chain은 보존되지 않았으며, 나중의 관측을 그 원문으로 대체하지 않는다.

이 판은 완료 효과 7개와 완료 학습 1개를 검증해 재사용한다. 완료 학습을 다시 실행하지 않는다. 이전 unknown 결과를 미회복이나 회복으로 덮어쓰지 않는다. 새 고정 평가 결과는 이전 학습과 결합한 이어 실행 결과로 기록한다.

## 실행 순서와 동일 조건

- 원천·참조·진단 결과·교정 방식·학습 횟수·고정 평가 기준은 V16을 유지한다.
- `case-05`: 고정 순서 → 명시 규칙 → 단일 모델 → 반복 에이전트.
- `case-06`: 명시 규칙 → 단일 모델 → 반복 에이전트 → 고정 순서.
- `case-07`: 단일 모델 → 원래 반복 에이전트 HOLD → 고정 순서 → 명시 규칙.
- `case-08`: 반복 에이전트 → 고정 순서 → 명시 규칙 → 단일 모델.
- 복합 결함의 재학습 seed는 앞서 등록했지만 실행하지 않은 6666·6667을 유지한다. 결과에 따라 seed를 고르지 않는다.

전체 16행은 완료 효과 재사용 7개, 완료 학습의 고정 평가 1개, 미시작 epoch 교정 7개, 원래 진단 HOLD 1개로 구성한다. 원래 HOLD에 재판단·교정 권한을 만들지 않는다. 새 승인과 영수증은 새 실행에 결합하고 이전 요청을 재소비하지 않는다.

## 검증 계약

완료 효과는 당시 Git source blob·등록 commit의 조상 관계와 실제 진단·학습·평가·영수증·자원 기록을 재검증한다. 현재 소스와 역사 실행 소스를 구분한다.

완료 학습은 원래 binding, 23필드 manifest, 별도 namespace 영수증, 원 request ID와 실효 run 이름, 교정 readback, 초기·최종 체크포인트, 설정, 정상 종료와 정리 증거를 결합한다. 고정 평가 디렉터리는 실행 전 만들어졌을 수 있으나 평가 jobs·보고서·owned 실행·입장 snapshot이 이미 있으면 이 경로로 받지 않는다. 학습 재실행은 허용하지 않는다.

새 고정 평가와 미시작 교정은 공용 lease 및 기존 GPU 입장 기준을 사용한다. 등록되지 않은 다른 프로세스를 종료하거나 허용 목록·메모리 상한·입장 판정 기준을 완화하지 않는다. 입장 조회 결과와 예외 chain·부가 receipt는 새 journal에 보존한다. journal은 원래 반환 객체와 판정·예외를 유지하며 승인이나 실행 권한을 생성하지 않는다.

새 SDK 예상은 고정 평가 1회와 미시작 교정 7개의 학습·평가 14회다. V16의 학습 전용 646.422초와 7개 완료 효과의 비용은 이전 비용으로 한 번만 센다. unknown 원장의 0 또는 null을 실제 사용량 0으로 바꾸지 않는다. 중첩 구간은 다시 합산하지 않는다.

진단과 회복은 별도 실제 phase다. 시간 합은 구성 구간의 합성값이며 연속 관측한 한 번의 사용자 작업 경과로 부르지 않는다. 재개 사이 대기·준비·실패 비용을 보존하고 전체 누락 비용은 unknown으로 둔다. 비독점 장치 메모리·전력·에너지 표본을 프로세스 전용으로 귀속하지 않는다. cold/warm 상태와 순차 실행 변동을 설명하며 작은 차이를 인과적인 속도·에너지 우위로 부르지 않는다.

## 예측과 결과 문구

기존 완료 효과는 원래 판정을 유지한다. 이어 실행이 회복 기준을 통과하면 해당 실제 결과와 분모를 기록한다. 미회복이면 원인 교정과 정책 회복의 차이를 유지한다. 확인 검사가 부족하면 추가 교정을 열지 않는다. 실행 기술 실패는 unknown과 소비 비용을 함께 남긴다.

전체 순서·원천·영수증·자원 결합을 확인하기 전에는 균형 비교 완료로 표시하지 않는다. 모든 방식의 결과가 같거나 반복 에이전트가 느려도 그대로 공개한다. 이전 실패와 새 이어 실행을 서로 다른 결과 폴더로 보존한다.

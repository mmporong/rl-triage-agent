# Brev 영상 자료 수집 사전등록 v7

v6는 점검 seed 2205의 정상 정책 20회 학습과 네 번의 프레임 캡처를 수행했다.
수동 캡처 설정과 세 annotator 등록은 확인됐으나 `IsaacReadTimes` 필드 검증에서
실패했다. 이후 USD 종료 단계가 반환하지 않아 부모의 시간 제한으로 종료됐다.
종료 뒤 GPU 프로세스는 없었다. 본 학습·고정 평가·모델 호출은 실행하지 않았다.
기존 사전등록과 결과는 보존한다.

설치된 SDK의 `IsaacReadTimes` 노드는 시각 필드 11개 외에 `execOut` 실행 포트를
정의하며, scalar annotator 수집 경로는 이를 함께 반환할 수 있다. v6는 반환 필드
원문을 저장하지 않아 이것이 실제 불일치 원인인지는 아직 확정하지 못했다.
v7은 검증 전에 모든 반환 필드의 이름·유형·안전하게 직렬화한 값과 RGB 해시를
새 저널에 보존한다. 동기화 점검에서는 RGB 원문도 함께 보관한다.

- 소스: `vision_brev_source_20261025_v7.json`.
- 렌더: `vision_brev_render_20261025_v8.json`.
- 실행 전 점검: `vision_brev_preflight_20261025_v7.json`.
- runtime: `vision-source-20261025g`.
- 핵심 seed: 2210·2211. 별도 점검 seed: 2206. 실행 직전 미사용 검사를 다시 수행한다.
- 실행 진입점: `bench/run_vision_brev_annotated_v1.py`.

새 어댑터는 기존 11필드 또는 그 11필드와 `execOut`의 조합만 받는다. `execOut`은
실행 포트 메타데이터로 분리하고, 나머지는 기존 시각 검증 함수에 전달한다.
누락·다른 추가 필드·시각 불일치·유효하지 않은 분모는 그대로 거부한다.
새 시각을 만들거나 허용 오차를 늘리지 않는다. 원문 저널은 정상 판정의 근거를
대신하지 않으며, 알 수 없는 값 유형은 유형 정보와 미지원 표시만 보존한다.

녹화와 점검의 공통 캡처 함수는 유지하고 어댑터를 호출할 수 있는 인자를 추가한다.
렌더 리소스는 annotator 분리 뒤 해제하며 환경 종료를 시도한다. 새 worker의 기본
앱은 `fast_shutdown=False`를 유지하고 `close(wait_for_replicator=False)`로 닫는다.
동기식 캡처에는 비동기 writer가 없으며, 결과·실패 파일은 앱 종료 전에 기록한다.
앱 종료가 반환하지 않으면 기존 시간 제한과 프로세스 종료 검사를 거쳐 실패로 남긴다.
이 리소스 정리가 관측된 USD 종료 대기를 해결하는지는 이번 점검에서 확인한다.

예측은 반환값의 추가 실행 포트를 분리한 뒤 기존 A→B→A 동기화 기준을 통과하는
것이다. 성공 조건은 시각·물리 상태·픽셀 검사와 정상 종료 증거 전체다.
원문을 보존하거나 필드 수를 맞춘 것만으로 통과하지 않는다. 실패하면 HOLD를
유지하며 점검 통과 전 본 수집을 시작하지 않는다. 모델 사용 준비는 여전히 false다.

그 밖의 예측·결과 문구·교정 승인 경계는 [v6](vision_brev_source_20261025_v6.md)를
따른다. 정상·결함·교정 각 두 건, 환경 4,096개·300회 갱신 여섯 건의 상한은 같다.
점검용 20회 학습은 정책 성능 표본에 합산하지 않는다. 같은 VM과 설치 환경을
재사용하며 비용은 v2의 실제 시작 요청부터 계산한다. 기존 점검·대기·실패·회수를
포함한 compute 상한 20 USD를 유지한다.

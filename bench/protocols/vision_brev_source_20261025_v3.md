# Brev 영상 자료 수집 사전등록 v3

## 재시험 범위

v2의 별도 seed 2202 정상 학습은 20회 갱신과 종료 증거 검증을 통과했다.
뒤따른 렌더 검사는 앱 초기화 중 exit -11로 끝났다. `libneuray.so`의
`libGLU.so.1` 의존성이 없다는 stderr와 `ldd` 출력을 확인했다.
Ubuntu 22.04의 `libglu1-mesa` 9.0.2-1을 설치한 뒤 같은 라이브러리의 누락 의존성은 0개다.
이것만으로 렌더 종료 원인이 모두 해결됐다고 판정하지 않는다.

v2 결과와 소비는 보존한다. v2에서는 핵심 학습·고정 평가·모델 요청을 실행하지 않았다.
이번 판은 공유 라이브러리 CPU 검사를 선행한 뒤 별도 seed 2203으로 20회 학습·렌더 점검을 다시 수행한다.
이는 환경 실행 확인이며 정책 성능을 보고 고른 재시험이 아니다.

## 결합과 실행 조건

- 소스: `vision_brev_source_20261025_v3.json`.
- 렌더: `vision_brev_render_20261025_v4.json`.
- 실행 전 점검: `vision_brev_preflight_20261025_v3.json`.
- 실행 전에 이 파일들과 결합 코드를 커밋한다.
- `check_vision_renderer_libraries_v1.py`의 누락·오류 없는 CPU 보고서를 확인한다.
  이 검사는 공유 라이브러리 의존성만 확인하며 실제 renderer 검사를 대신하지 않는다.
- 기존 환경의 고정 버전과 소유 GPU 입장을 다시 확인한다. source seed 2200·2201, 점검 seed 2203의 미사용 상태를 로컬·원격에서 재검사한다.
- 소유 VM·compute 시작 시각은 v2와 같다. 시작 요청부터 준비·대기·점검·회수까지 합한 20 USD 상한을 유지하며 새 판을 이유로 비용 시계를 초기화하지 않는다.

## 예측·판정 기준

공유 라이브러리 검사와 새 20회 학습·렌더 점검이 통과할 것으로 예상한다.
실제 단계별 산출물·해시·종료·동기화 증거와 다음 action의 자원 조건이 유효할 때만 본 수집을 시작한다.
다시 실패하면 실패 기록을 보존하고 본 수집을 보류한다.

핵심 학습은 seed 2200·2201의 NONE·F1·CORRECTED 각 300회, 환경 4,096개, 여섯 건 상한을 유지한다.
이번 수집은 정상·결함 네 건만 실행하며 교정 두 건은 후속 고리의 유효 승인 뒤에만 실행한다.
정상은 기존 고정 평가 통과, F1은 이동 추종 미통과를 예상한다.
정상 대조 미통과나 F1 실패 부재를 보존하며 유리한 결과를 위한 seed 교체를 하지 않는다.

같은 Play의 영상·명령·운동·시각을 수집하고 checkpoint별 렌더 확인을 통과한 자료만 후속 입력 후보로 내보낸다.
동일 정책의 두 영상 구간을 독립 학습 사례로 세지 않는다. 단계별 자료를 회수해 SHA를 대조한 뒤 소유 VM을 Stop한다.
완료 여부가 불명확한 pending은 자동 재전송하지 않는다.

## 결과 문구

- 점검 통과: “시스템 의존성을 보완한 환경에서 짧은 학습과 등록 렌더 조합의 실행을 확인했다. 모델 판단·회복 효과는 별도 평가 대상이다.”
- 점검 재실패: “환경 의존성 보완 뒤에도 실행 전 점검을 통과하지 못해 본 수집을 보류했다.”
- 소스·평가·녹화 결과 문구와 구간 독립성은 [v2 사전등록](vision_brev_source_20261025_v2.md)의 판정표를 유지한다.

이미 본 보상 결함과 환경 실패를 바탕으로 설계한 판이다. 등록 조건 확인과 처음 보는 결함에 대한 대응을 구분한다.

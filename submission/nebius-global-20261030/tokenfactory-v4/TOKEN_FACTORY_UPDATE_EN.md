# Proposed Token Factory update

## Platform use

We have now made runtime calls to NVIDIA Nemotron 3 Super and Nemotron 3.5 Super VL on Nebius Token Factory. A separately registered investigation caller passed eight actual 3.5 replies through the existing action validator and investigation consumer. The model cited recorded training facts and selected a registered inspection or returned HOLD. Each inspection remains a proposal requiring separate authorization.

The completed R1 repair in the existing demo used NVIDIA-hosted Nemotron 3 Super. Its repair metrics are not attributed to this new Token Factory experiment. Simulation and synchronized normal/F1 capture on Brev-provisioned Nebius L40S compute are also separate records.

## What the comparison showed

Both initial-data policies produced valid decisions in all four sessions. The identical-reference control returned HOLD twice per policy; the recorded candidate produced two inspection proposals per policy. The optional training read was not selected, so this experiment does not demonstrate a retrieval benefit. The recorded usage-price estimate was $0.0080469 for eager context and $0.0063120 for on-demand context, without applying cache discounts. This small development comparison does not establish a cost advantage, generalization, or a new learning result. Account balance, promotional redemption and invoiced charges remain unverified.

## Feedback from actual use

The 3.5 endpoint accepted the tested structured-output subset, including current action/target/fact enums, required fields, minItems, nullable targets and strict output. An earlier trial rejected uniqueItems. We retained citation uniqueness checks in the host. A versioned capability table for supported JSON Schema keywords would make provider registration easier. Exact model IDs and per-decision request hashes also helped keep the Token Factory and NVIDIA-hosted paths distinct.

Publication requires the owner to integrate the measured caller source and this evidence with the existing application. This candidate does not replace the pending source, approval, resource or GPU evaluation work.

The accompanying core replay CLI reconstructs local investigation contexts from the published training summary and confirms that the model-facing messages and params match the recorded Token Factory requests. It runs the original investigation and inspection-request functions. This offline demonstration does not require the original private capsule, grant an approval, make a new API request, or establish a new GPU recovery result.

Platform use and feedback

Nebius Token Factory
We made runtime calls to NVIDIA Nemotron 3 Super and Nemotron 3.5 Super VL. A separately preregistered comparison passed eight actual 3.5 replies through the existing investigation and inspection-request functions. The host accepted each structured decision and checked the cited training facts. Inspection proposals still require separate execution authorization.

The 3.5 endpoint accepted the tested response-format subset, including the available action, target, and fact-ID enums, required fields, nullable targets, and minItems. An earlier request rejected uniqueItems, so the host retained citation-uniqueness validation. A versioned model-ID and JSON Schema capability table would make provider configuration easier to reproduce.

Brev-provisioned Nebius compute
Isaac Lab simulation and synchronized normal/F1 capture ran on Nebius L40S compute provisioned through Brev, with the actual registered machine type gpu-l40s-d.1gpu-16vcpu-96gb. An exportable receipt joining provider identity, lifecycle, machine type, and artifact hashes would help document compute use without exposing private paths.

The request records establish actual Token Factory use. Promotional credit redemption, account balance, and invoiced charges have not been verified. The new API experiment does not inherit the earlier NVIDIA-hosted R1 repair result.

NVIDIA-hosted NIM development evidence
Historical same-input NIM requests had 39.66% and 56.44% shorter mean API waits in two task groups. We do not apply those percentages to Token Factory, GPU training, or the whole investigation. Quality outcomes were mixed, so a useful provider comparison should retain validity and citation checks beside latency. Reporting queue time, TTFT, served revision and deployment precision would help distinguish service behavior from model-level causes.

Vision and the actual inspection loop
Policy-frame observation replies were valid in 18/18 cases and corresponded to fixed-evaluation groups in 17/18. Separate auxiliary observations were not decision inputs. A later NIM3.5 workflow connected a model-selected actual reward inspection to a correction proposal, retraining and evaluation; the new policy remained not_recovered. We retain behavioral evaluation as the recovery decision and do not infer a benefit from images being present.
